# Codex 多会话工作台设计

日期：2026-07-20  
状态：已确认，可实施  
目标平台：Windows 10/11 x64

## 1. 产品目标

构建一个独立 Windows 应用，让用户在同一个一级界面中同时阅读和操作多个本机 Codex 线程。每个线程都是一个完整的小型对话窗口，直接呈现标题、最近对话、运行状态和输入框；用户无需进入详情页即可继续多个线程。

首版以“操作”为核心，不做全局统计仪表盘，不设置常驻左侧导航，也不展示任务进度汇总。

## 2. 已确认的视觉与布局

- 采用“等分对话网格”。
- 采用“雾白、清爽、轻量阴影”的桌面视觉风格。
- 应用顶部仅保留窗口模式、布局和打开线程等高频操作。
- 每个线程卡片包含：
  - 线程标题；
  - 清晰的状态标记；
  - 用户与 Codex 的最近对话；
  - 一级界面内的多行输入框；
  - 发送、停止、最小化和关闭操作。
- 不显示左侧导航、任务进度统计、今日完成数量或活动时间线。

## 3. 默认交互

### 3.1 打开与排列线程

- 首次启动时自动打开最近更新的 4 个非归档线程。
- 后续启动恢复上次打开的线程集合和窗口位置。
- 网格根据窗口宽高自动排列 1–6 个对话窗口：
  - 1 个：单窗；
  - 2 个：双列；
  - 3–4 个：2×2；
  - 5–6 个：3×2。
- 同屏达到 6 个后，“打开线程”仍允许更换当前窗口，但不会无限压缩现有对话。
- 关闭线程卡片只会从工作台移除，不会删除或归档 Codex 线程。

### 3.2 线程选择器

- “打开线程”在当前窗口上方显示模态选择层，而不是跳转到新页面。
- 选择器展示所有可见的本机 Codex 线程，支持搜索标题或预览文字。
- 已打开的线程有明确标记；选择一个未打开线程后立即加入网格。
- 选择器支持刷新，读取 Codex 最新线程列表。

### 3.3 对话

- 打开线程时加载用户消息和 Codex 文本回复；命令、工具调用和内部推理不占据首版主消息流。
- 每个线程最多先显示最近 80 条用户/助手消息，避免极长线程拖慢界面。
- 空闲线程发送文本时：
  1. 通过 `thread/resume` 加载线程；
  2. 通过 `turn/start` 创建新回合。
- 线程正在运行时继续输入，使用 `turn/steer` 将文本追加到当前回合。
- `Enter` 发送，`Shift+Enter` 换行。
- 运行中显示“停止”按钮，调用 `turn/interrupt`。
- Codex 回复通过 `item/agentMessage/delta` 流式更新；回合完成后用最终消息替换临时文本。

### 3.4 状态

- `进行中`：线程状态为 active 或本地已发送但尚未收到完成事件，使用绿色。
- `已完成`：最近回合 completed，使用中性绿色。
- `已停止`：最近回合 interrupted，使用灰色。
- `出错`：线程为 systemError 或最近回合 failed，使用红色，并在卡片内显示可读错误。
- `未载入`：线程为 notLoaded 且尚未在工作台中恢复，使用灰色。
- 收到命令或文件修改审批请求时显示 `需确认`，并提供“允许本次”和“拒绝”按钮；首版不会自动批准。

### 3.5 桌面与全屏

- “桌面”模式使用普通可调整窗口，保留系统标题栏按钮和上次窗口尺寸。
- “全屏”模式铺满当前显示器并隐藏系统边框。
- 再次切换桌面模式时恢复进入全屏前的窗口位置与尺寸。

## 4. Codex 接入

使用本机 Codex CLI 0.142.5 提供的 `codex app-server`：

- 通过 `stdio` 启动子进程；
- 使用换行分隔的 JSON-RPC 消息；
- 连接后先发送 `initialize`，再发送 `initialized`；
- 核心方法：
  - `thread/list`
  - `thread/read`
  - `thread/resume`
  - `turn/start`
  - `turn/steer`
  - `turn/interrupt`
  - `thread/archive`
  - `thread/name/set`
- 核心通知：
  - `thread/status/changed`
  - `turn/started`
  - `turn/completed`
  - `item/started`
  - `item/completed`
  - `item/agentMessage/delta`

应用优先解析 PATH 中可执行的 `codex.exe`，失败时回退到 `%USERPROFILE%\.codex\.sandbox-bin\codex.exe`。应用不会读取 `auth.json`、Token、Cookie 或其他凭据；认证完全由 Codex CLI 自己管理。

## 5. 架构

### 5.1 技术栈

- .NET 8
- WPF
- C# 12
- `System.Text.Json`
- 不引入运行时第三方 UI 或 MVVM 依赖
- xUnit 用于自动化测试

### 5.2 组件边界

`CodexProcessLocator`
: 只负责找到可运行的 Codex CLI。

`JsonRpcConnection`
: 只负责 JSONL 读写、请求 ID、响应匹配、通知和服务器请求分发。

`CodexAppServerClient`
: 封装 Codex 方法名和参数；负责初始化、线程读写和回合控制。

`ThreadProjection`
: 把 app-server 的动态 JSON 映射为稳定的工作台线程、消息和状态模型。

`WorkspaceStore`
: 把打开线程 ID、窗口位置和显示模式保存在 `%LOCALAPPDATA%\CodexThreadWorkbench\workspace.json`。

`MainViewModel`
: 管理已打开线程、选择器、窗口模式和全局错误，不处理具体 JSON。

`ThreadCardViewModel`
: 管理单个线程的消息、输入、发送/转向/停止和审批状态。

`MainWindow`
: 只负责 WPF 视觉树、窗口模式切换和键盘交互。

### 5.3 数据流

1. 应用启动 `codex app-server` 并初始化连接。
2. `thread/list` 返回线程摘要；工作台恢复最多 6 个上次打开线程，否则打开最近 4 个。
3. 每个打开线程调用 `thread/read(includeTurns: true)`，投影出消息。
4. 用户在任意卡片输入文字：
   - active：`turn/steer`；
   - 其他状态：`thread/resume` 后 `turn/start`。
5. app-server 通知进入 `CodexAppServerClient`，按 `threadId` 路由到对应卡片。
6. 卡片增量更新消息和状态，WPF 通过属性通知刷新。

## 6. 错误与安全

- Codex CLI 不存在：显示清晰的阻塞页，列出检查路径和修复提示。
- app-server 退出：所有卡片显示离线，提供“重新连接”按钮。
- JSON-RPC 请求失败：错误只显示在相关卡片；不会让其他线程失效。
- 发送失败：保留用户输入，避免内容丢失。
- 审批请求：必须由用户显式允许或拒绝；应用不会默认同意。
- 关闭应用：先取消读循环，再结束由本应用启动的 app-server 子进程。
- 不永久保存聊天内容，只保存线程 ID 和窗口偏好。

## 7. 测试与验收

自动化测试覆盖：

- Codex CLI 路径解析；
- JSON-RPC 请求/响应匹配、通知分发和服务器请求；
- 线程 JSON 到消息/状态模型的投影；
- active 时使用 steer、idle 时 resume + start；
- 审批响应只发送用户选择；
- 工作台设置持久化与损坏文件回退；
- 1–6 个窗口的网格行列计算；
- 全屏前窗口位置的保存与恢复逻辑。

人工验收覆盖：

- 应用显示真实本机线程；
- 同屏 4 个线程均可独立输入；
- 两个线程能并行运行并流式更新；
- 运行、完成、停止、出错和需确认状态清晰；
- 关闭卡片不会归档或删除线程；
- 桌面/全屏往返后窗口位置正确；
- 125%、150% DPI 下布局和文字清晰。

## 8. 首版不包含

- 云端远程主机线程；
- 文件附件和图片输入；
- 语音或实时模式；
- 线程删除；
- 全局统计与进度仪表盘；
- 自定义主题编辑器；
- 自动批准命令或文件修改。
