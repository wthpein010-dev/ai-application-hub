# Codex 对话消息样式设计

**日期：** 2026-07-22
**状态：** 用户已确认方案 A
**目标：** 去掉 Codex 长回复的整块底框，让对话层级更接近 Codex 自身界面，同时保留用户消息的气泡识别。

## 视觉规则

- 用户消息右对齐，保留浅绿色背景、圆角和内部留白。
- 用户气泡限制最大宽度，短消息不被强行拉宽，长消息自动换行。
- Codex 消息左对齐，背景完全透明，不显示边框或大块底色。
- Codex 消息在正文上方保留小号“Codex”角色标识，使用次级文字色和紧凑间距。
- Codex 正文使用更宽的可读区域；长文本依靠段落间距、行高和消息间留白区分，不依赖矩形容器。
- 流式回复与最终回复使用同一布局，避免内容完成时发生跳动。

## 结构与职责

- `ThreadCardView.axaml` 负责消息模板、角色标识、内外边距和最大宽度。
- 角色转换器只负责用户/助手的对齐、背景和角色可见性，不引入聊天内容逻辑。
- 现有 `ChatMessage` 数据结构、消息投影、流式更新和发送流程保持不变。

## 交互与边界

- 用户消息仍能通过右侧气泡快速识别。
- Codex 回复无论多长都不出现底框；文本仍可自动换行，横向滚动条保持禁用。
- 多线程卡片、审批提示、错误提示和输入区样式不变。
- Windows 与 macOS 使用同一 Avalonia 模板，保持跨平台一致。

## 验证

- 新增桌面视图回归，验证消息模板包含独立的用户气泡和无背景 Codex 内容区。
- 验证用户背景非透明、Codex 背景透明，且 Codex 角色标识只在助手消息中可见。
- 运行 Debug 与 Release 全套测试。
- 重新发布 Windows x64 包，更新固定交付目录中的 EXE/ZIP；桌面快捷方式继续指向该 EXE。
- 启动应用进行 Windows 实际视觉检查，确认长回复没有底框、短消息对齐清晰、界面无截断。

## 非目标

- 不修改消息协议、历史消息数量、Markdown 渲染或流式回复机制。
- 不改动线程卡片整体布局、状态栏、审批卡片或输入框。
- 本次不自动发布 GitHub Pages 或 macOS 包，除非用户另行要求。
