# Codex Thread Workbench Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build and package a Windows desktop application that displays up to six real Codex threads as directly operable conversation windows in an equal grid.

**Architecture:** A .NET 8 WPF shell uses a process-backed JSONL connection to the documented Codex app-server. Protocol JSON is isolated behind a client and projection layer; view models expose stable conversation/status state to a light WPF UI and persist only thread IDs plus window preferences.

**Tech Stack:** .NET 8, C# 12, WPF, `System.Text.Json`, xUnit

## Global Constraints

- Target Windows 10/11 x64 with `net8.0-windows`.
- Use the confirmed equal conversation grid and light “雾白” visual direction.
- Show no persistent left navigation or statistics dashboard.
- Keep 1–6 threads open; restore the previous set or use the four most recent threads.
- Use `codex app-server` over stdio JSONL and never read Codex credential files.
- Do not persist chat text.
- Never auto-approve command or file-change requests.
- Closing a card removes it only from the workspace.
- Use app-server API shapes generated by the installed Codex CLI 0.142.5.
