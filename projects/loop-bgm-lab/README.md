# 循环乐工房

循环乐工房是一个 local-first 的循环背景音乐工作台。它在浏览器本地分析参考音频、建立五批单变量提示词、登记 Suno Create 结果、比较候选，并把来源与许可证据一起保存成可跨电脑迁移的项目。

## 推荐流程

1. 导入参考音频并检查聚合画像；原始字节、绝对路径和本机文件名不会写进项目。
2. 每次只调整一个变量，复制提示词到 Suno Create；工具里的 50 credits 只是计划，不代表账户实时余额。
3. 先登记本次 Create 和一至两个输出链接，再把下载文件作为 `Suno 结果` 导入；来源会精确绑定到运行及输出序号。
4. 外部音乐或本地原创必须先进入授权台账，并以音频字节的 SHA-256 精确匹配后才能成为候选。
5. 人工填写评分、复盘和处置；“研究最佳”只表示当前听感偏好，不等于发布资料完整。
6. 导出项目 JSON 或 Markdown，到另一台电脑继续工作。

## 四种候选来源

- `suno`：明确绑定到已经登记的 Suno 运行和其中一个输出。这只证明生成来源，不是候选的许可证据；当前发布规则仍会保留 `missing-license-evidence` 阻塞。
- `external`：来自第三方素材站或作者，必须绑定同哈希的外部许可证据。
- `local-original`：用户声明的本地原创素材，必须绑定同哈希且权利链状态为 `user-declared-original` 的记录。
- `legacy-unknown`：旧项目迁移后的待确认来源。系统不会从链接、文件名或历史自动猜测；只有明确选择证据后才能重新分类。

## 许可证据包与项目交接

许可证据包是独立的 JSON：导入前会显示新增、跳过、冲突和发布阻塞项；预检不修改项目，只有通过结构和全项目冲突校验后才可应用。外部候选包的 schema v3 `manifest.json` 也可转成这一证据格式。ZIP、Markdown、超限、含私密路径、直接媒体/下载 URL，或带签名参数的地址会被拒绝；证据 URL 必须是可公开复核的 HTTPS 页面。

项目 JSON/Markdown 则保存完整的研究状态，包括画像、批次、运行、候选、实验和授权台账。它们不包含音频本体、原始样本或可逆波形、Cookie、Token、API key、恢复密钥、浏览器会话、绝对路径、个人文件名、`file:`/`blob:` URL 或直接传输元数据。

## 发布门禁的边界

- SHA-256 只证明当前字节的身份与完整性，不证明著作权归属或商业使用权。
- `preview-only` 只能用于研究试听。原始文件是不同字节：用于交付前必须计算新 SHA-256、为新哈希建立许可证据，并把原始文件作为新候选重新导入和绑定；不能沿用预览候选或旧许可证行的哈希。
- `source-declaration-only` 表示记录了来源页面的声明，仍需要权利链复核。
- CC-BY 需要完整署名；NC、ND、SA 和未知许可按各自限制保守处理。
- “记录门禁通过（非法律清白）”只表示工具要求的资料齐全，不构成法律意见、版权清场或不侵权保证。

## Suno 自动化边界

当前工具提供提示词队列、运行/输出登记和本地比较，但不会调用未经验证的接口，也不会绕过登录、额度、验证或下载限制。只有官方 API 的认证、用量、生成、状态、下载和错误契约全部得到可靠证据后，自动传输层才应启用。在此之前，生成和下载仍通过用户已登录的官方 Suno 页面完成。
