# Paws 2D 工程网格与试玩三道具设计

日期：2026-07-28

状态：用户已确认设计

适用范围：`projects/paws-level-editor` 的 2D 编辑视图、2D/3D 试玩和公开演示

## 目标

让网页关卡编辑器继续复用 Unity 工程的当前棋盘与道具规则：

- 2D 编辑视图显示 Unity `SheepLevelEditorController.DrawFieldGrid` 同口径的固定 7×8 田字棋盘，不再用铺满屏幕的通用淡网格代替工程棋盘。
- 试玩底部显示工程原图“随机/洗牌、配对、撤回”三个道具。
- 三个道具每局各 1 次，直接点击使用，不接广告领取流程。
- 道具只有执行成功才消耗；执行失败不消耗；重新试玩或换种子会恢复次数。
- 2D 与 3D 试玩共用同一局状态，切换视图不会恢复次数或回滚道具效果。

## 不在本轮范围

- 不移植 Unity 广告领取、弹窗、埋点、音效或完整 DOTween/Spine 道具演出。
- 不修改 Unity 工程源码、资源或关卡 JSON；Unity 工程仅作为规则和资源的只读来源。
- 不改变关卡编辑历史中的撤销/重做；试玩“撤回道具”与编辑器 `Ctrl+Z` 是两个独立功能。
- 不改变 AI 生成、难度评分、通关率评估或关卡保存格式。

## 方案选择

采用“Canvas 网格 + 共享试玩引擎”方案：

- 网格直接由 `Canvas2DView` 绘制，天然跟随现有缩放、平移和适配，不使用容易与棋盘错位的 DOM/CSS 叠层。
- 道具规则进入 `createPlaySession`，UI 和控制器只分发命令并展示事件。这样 2D、3D 和自动化测试共享同一规则。
- 使用 Unity 原始 PNG 按钮；动画只保留短促的按压、禁用和结果反馈，不移植完整广告与轨迹演出。

## 2D 工程棋盘网格

### 数据口径

默认棋盘保持工程当前常量：

- 宏格：`7 × 8`
- 每个宏格：`8 × 8` 微格
- 单砖尺寸：`8 × 8` 微格
- 每个宏格中央十字：横纵各位于 `+4` 微格

绘制使用当前文档的 `board.width`、`board.height`；现有产品门禁仍保证新建和 AI 关卡为 7×8。若导入历史兼容关卡带有其他合法尺寸，网格按文档尺寸绘制，不裁切数据。

### 视觉与层级

`Canvas2DView.drawFieldGrid(context)` 在草地之上、砖块之下绘制：

1. 以棋盘 `(0, 0)` 到 `(width × 8, height × 8)` 为唯一边界。
2. 每 8 微格绘制一条主格线，颜色为白色、透明度 `0.72`、线宽 `1px`。
3. 每个主格内部在 `+4` 微格处绘制中央十字，颜色为白色、透明度 `0.5`、线宽 `1px`。
4. 棋盘内容外框绘制黄色边线，颜色接近 Unity `rgba(255, 224, 51, 0.85)`、线宽 `2px`。
5. 下边标注 X 微坐标 `0, 8, 16 … width×8`，左边标注 Y 微坐标 `0, 8, 16 … height×8`，并显示 `X`、`Y`。
6. 网格只在 2D 编辑模式显示；试玩继续使用实机草地舞台，避免工程辅助线干扰真实试玩观感。

现有铺满画布的无限淡网格删除，避免同时出现两套尺度不同的网格。

## 试玩底部道具

### 资源与布局

从 Unity 当前目录只读复制：

`Assets/GameRes/Runtime/UI/LevelScene/Sprites/Atlas1`

发布资源：

- `btn_random.png`：随机/洗牌
- `btn_magnet.png`：配对
- `btn_rollback.png`：撤回

三个按钮固定在试玩舞台底部中央，顺序与工程一致：随机、配对、撤回。按钮使用原图自带中文标题；网页的 `aria-label` 与 `title` 使用“随机”“配对”“撤回”。

每个按钮显示一次可用状态：

- 可用：正常亮度，次数为 `1`。
- 操作失败：保持可用，并通过 Toast 说明失败原因。
- 操作成功：次数变为 `0`，按钮禁用并覆盖 `40%` 黑色阴影。

“重新试玩、锁定种子、适配舞台”保留为编辑器测试控制，但与三个游戏道具分离，不混排在底部道具组中。

### 试玩快照

`createPlaySession().getSnapshot()` 新增：

```js
tools: {
  shuffle: { remaining: 1 },
  match: { remaining: 1 },
  undo: { remaining: 1 },
}
```

重新试玩或新种子调用 `restart()` 时恢复三个 `remaining` 为 `1`。切换 2D/3D 只重新挂载渲染器，不重建 session，因此次数保持。

## 道具规则

### 随机

新增 `playSession.useShuffleTool()`：

1. 只处理尚未移除且不在暂存槽的棋盘砖块。
2. 保留砖块 UID、坐标、层级、翻转状态和图案多重集合，只重新排列 `type`。
3. 最多尝试 64 个确定性洗牌候选；使用当前局种子派生候选种子，测试可复现。
4. 优先选择当前可操作区至少有两对的候选；找不到时接受至少一对可操作的候选。
5. 若仍没有可继续配对的候选，不改变局面、不消耗次数并返回 `tool-rejected`。
6. 成功后刷新遮挡与选中状态，返回 `tool-shuffled` 并消耗随机道具。

动画简化为按钮反馈和棋盘短暂淡出/淡入，不实现 Unity 约 1.7 秒的环绕轨迹。

### 配对

新增 `playSession.useMatchTool()`：

1. 优先在当前可交互砖块（棋盘可用砖和暂存槽砖）中寻找同图案一对。
2. 若表层没有配对，在所有未移除砖块中按“上层优先、Y 大优先、X 小优先”寻找同图案一对，模拟 Unity 拉取被遮挡对子。
3. 找到后直接移除该对、清理可能占用的暂存槽、刷新遮挡和胜负状态。
4. 成功返回 `tool-match-removed` 并消耗配对道具；没有任何对子时返回 `tool-rejected`，不消耗。
5. 道具配对不触发特殊砖额外清除，避免一次道具使用扩大成未确认的连锁效果。

动画简化为目标砖短暂高亮后消失。

### 撤回

新增 `playSession.useUndoTool()`：

1. `stash()` 成功时把砖块 UID 压入试玩暂存历史。
2. 使用道具时从历史末尾向前寻找仍在暂存槽的最近砖块，跳过已经被配对移除的旧记录。
3. 找到后清空对应槽位、删除 `stashedSlot`、恢复棋盘遮挡状态并返回 `tool-undone`。
4. 暂存历史中没有可撤回砖块时返回 `tool-rejected`，不消耗。
5. 成功撤回只回到该砖原有坐标和层级，不改变其他砖块。

## 控制器与事件

`WorkbenchController` 新增三个按钮绑定和一个统一入口：

```js
usePlayTool(toolName)
```

控制器根据 `shuffle | match | undo` 调用对应 session 方法，然后：

1. 读取新快照。
2. 刷新当前 2D/3D 渲染器。
3. 根据事件显示明确 Toast。
4. 更新按钮次数与禁用状态。

控制器不直接修改砖块、暂存槽或次数，避免 UI 与试玩引擎状态分叉。

## 错误处理

- 随机时剩余棋盘砖少于 2 张：提示“剩余砖块不足，无法随机”，次数不消耗。
- 随机找不到至少一对可操作候选：提示“当前局面无法生成可用配对”，局面原子回滚，次数不消耗。
- 配对找不到任何同图案对子：提示“没有可配对的砖块”，次数不消耗。
- 撤回没有仍在暂存槽的砖块：提示“暂无可撤回的砖块”，次数不消耗。
- 已用完的道具按钮禁用；session 方法再次被调用时仍返回拒绝事件，不修改状态。
- 任一道具执行后重新计算 `won`、`deadlocked`，成功配对可正常触发通关。

## 测试与验收

### 自动化

- 网格纯布局测试：7×8 主线数量、每格中央十字、坐标标签和黄色边框。
- 2D 源码测试：只绘制有边界的工程网格，不再绘制无限屏幕网格；试玩模式不显示辅助网格。
- 资源测试：三个 PNG 与 Unity 源文件字节一致且可解码。
- 试玩引擎测试：
  - 每局三个道具各 1 次，`restart()` 恢复。
  - 随机保留图案多重集合并产生可用对子。
  - 随机失败原子回滚且不消耗。
  - 配对优先清可操作对子，并能拉取被遮挡对子。
  - 撤回恢复最近仍在槽中的砖块，并跳过已经消除的历史项。
  - 失败不消耗，成功只消耗一次。
  - 切换 2D/3D 不重置道具。
- 浏览器回归：真实点击三个按钮，断言砖块/暂存槽/次数变化、禁用态、Toast、2D/3D 状态一致及浏览器错误为 0。

### 视觉验收

- 2D 编辑：网格严格落在棋盘内容边界，主格和中央十字与砖块 8 微格坐标对齐，缩放和平移后不漂移。
- 2D 试玩：底部三个工程原图按钮顺序、大小、亮暗状态清晰，不遮挡暂存槽和砖块。
- 3D 试玩：同一组三道具可用且次数与 2D 一致。
- 桌面和 390×844 均无横向溢出。
