# Paws 关卡编辑器实机视觉还原设计

日期：2026-07-21

状态：已批准（用户要求直接开发）

## 目标

在不牺牲桌面关卡编辑效率的前提下，让中央编辑舞台、2D/3D 砖块和试玩界面尽量接近 Unity 游戏的实际画面。动画允许简化；关卡数据、编辑、试玩、3D 检查和浏览器本地保存逻辑保持不变。

权威视觉参考是 Unity 工程中的 `snapshot_level_0020.png`，公开网页只复制获得授权的美术文件，不包含工程绝对路径。

## 方案

采用“编辑器外壳 + 实机游戏舞台”。左侧关卡库、顶部工具栏、右侧属性面板继续使用高密度桌面布局；中央舞台替换为绿色草地、实机砖块、关卡标题和试玩槽位。编辑模式保留网格、选择框、层级标签；试玩模式隐藏网格，突出游戏画面。

不采用整页手机比例模拟，因为会明显压缩桌面编辑空间；也不只做颜色替换，因为无法解决砖块底板、暂存槽和按钮与实机不一致的问题。

## 资源映射

公开资源统一放在 `projects/paws-level-editor/assets/gameplay/`：

- `block_bg.png`：120×135，砖块奶油色顶面、深绿描边和绿色底边。
- `ui_tile_lock_mask.png`：120×135，遮挡/翻面蒙层。
- `bg-47bd7f.png`：实机草地底色纹理。
- `grass.png`：稀疏草纹装饰。
- `Setting.png`：绑定“适配画布”功能。
- `btn_random.png`：绑定“重新随机”功能。
- `btn_replay.png`：绑定“重新试玩”功能。
- `play_save2.png`：双暂存槽框体。

38 张 `assets/blocks/block_*.png` 继续作为透明图案层，与 `block_bg.png` 等比例叠合。资源均从 Unity 工程复制，原文件不修改。

## 布局与交互

中央舞台常驻简化实机 HUD：左上设置图标实际执行当前视图的适配；顶部黑色标题显示当前关卡名称。编辑模式降低 HUD 视觉权重，试玩模式恢复实机感。

原试玩工具不再使用普通文本按钮：重玩与洗牌使用真实按钮皮肤；种子锁定和适配保留为紧凑辅助控件。所有按钮继续调用已有控制器方法。

2D 试玩时在画布下方绘制 `play_save2.png`，砖块按两个槽位的真实内框位置放置。右键牌面暂存、左键配对的规则不变。

移动端仍为只读试玩；画布、HUD 和按钮按可用宽度缩放，左右面板维持抽屉行为。

## 2D 渲染

砖块的逻辑占位仍是 8×8。视觉图以 120:135 比例向下延伸：先绘制 `block_bg.png`，再在相同矩形绘制 `block_*.png`，避免透明图案被方形容器裁切。图片加载前使用接近实机的后备底板，加载完成后自动重绘。

不可操作牌叠加 `ui_tile_lock_mask.png`；选择态使用清晰的金黄色描边。层级标签只在编辑模式显示，避免污染试玩效果。

## 3D 渲染

3D 顶面纹理从真实底板和图案的上方 120×120 区域合成，侧面使用深绿色材质，保持砖块厚度和阴影。草地场景使用实机绿色，编辑模式显示辅助网格，试玩模式隐藏网格。

试玩时增加贴地的 `play_save2.png` 双槽平面，已暂存牌落在对应槽位。轨道相机、点选、右键暂存和视图适配逻辑不变。

## 动画与性能

仅保留短促的 CSS 悬停/按压反馈与现有选择态轻微浮动。纹理按类型缓存，销毁视图时释放 WebGL 材质和纹理；资源失败时显示可操作的后备图，不阻塞编辑或试玩。

## 验收

- 静态测试校验 8 个 gameplay PNG 的文件名、尺寸和页面引用。
- 2D/3D 源码契约校验底板与图案合成、锁定蒙层、草地背景、试玩双槽和真实按钮绑定。
- 桌面浏览器验证默认关卡打开、编辑/试玩、2D/3D 切换、重玩、洗牌、暂存无控制台错误。
- 1440×900 与移动端画面无溢出，编辑工具不被试玩控件遮挡。
- 因入口和样式属于教程录屏证明源，发布前真实重录并通过媒体哈希、章节和解码门禁。
