# AI Application Hub 交互式项目图鉴设计规格

日期：2026-08-25

状态：已确认视觉方向，待独立预览验收

适用范围：AI Application Hub 主页独立改版预览；用户确认预览前不修改或发布生产主页

## 目标

把当前以文字卡片为主的项目总览升级为一个信息直观、交互明确、视觉有记忆点的“交互式项目图鉴”。页面必须继续承载现有 29 个项目的真实数据、原始顺序、筛选类别、演示、视频和 Windows/macOS/iOS 入口，同时降低重复筛选、平台信息分散和卡片视觉同质化带来的阅读成本。

## 参考提炼

- MotionSites：采用“先看项目画面、再读信息”的预览节奏和紧凑分类导航，不采用超大营销首屏。
- React Bits：采用轻量点阵背景、磁吸反馈和状态驱动的切换动效，不采用全屏 WebGL 或紫色主调。
- Uiverse：统一按钮、搜索、状态徽标和焦点反馈的微组件质量，不混用不同风格的控件。
- Anime.js：只把时间轴、交错入场和选择过渡用于解释层级变化；不让普通点击反复触发整页动画。
- Aceternity UI：采用清晰的组件目录、Bento 节奏、预览卡和主题切换，不复制其付费导航和营销结构。

## 视觉系统

- 默认主题为干净白色，主体文字使用接近黑色的高对比色。
- 应用使用薄荷绿，小程序/小游戏使用橙色，工程体验使用蓝色；颜色用于识别类型，不形成单一色调页面。
- 背景使用低密度点阵和轻微指针响应，避免渐变色块、装饰光球和影响阅读的动态噪声。
- 卡片圆角不超过 8px；阴影弱化，主要通过边框、留白、图片和状态强调建立层级。
- 正文不低于 13px，辅助标签不低于 12px；默认文字对比度达到 WCAG AA。

## 页面结构

### 1. 顶部导航

保持总览、应用、平台和维护四个入口。左侧显示站点名称，右侧集中搜索、主题切换和编辑入口。滚动后导航缩为紧凑状态，但不改变可点击区域大小。

### 2. 精选项目舞台

首屏使用一块完整的全宽展示带，而不是左右两个相互割裂的卡片。左侧承载项目类别、标题、摘要、使用场景、平台状态和主要入口；右侧显示项目真实截图或现有视觉资产。背景点阵只在该区域轻微响应指针。

上一项和下一项按钮位于舞台边缘垂直中线，底部只保留序号和进度。点击下方任意项目卡时，舞台同步更新；舞台切换使用短距离遮罩或交叉淡入，不重新播放页面入场动画。

### 3. 项目统计

总数、应用数和小游戏数压缩为舞台下方的一条辅助信息，不再占据独立大面积。统计只用于建立规模感，不与主要入口竞争。

### 4. 吸顶筛选轨道

保留六个已确认分类：插件工具、辅助工具、生活工具、网页情报、桌面工具、内容工具。分类按钮、搜索和排序放在同一条吸顶轨道中，删除与六类页签重复的细分类下拉。

筛选后卡片在原容器内平滑重排；清空筛选不重新播放首次入场动画。搜索匹配名称、摘要、使用场景和关键词。

### 5. 项目图鉴

桌面端使用四列网格，平板两列，手机单列。每张卡片包含：真实预览图、类型标签、项目名称、一段不重复的概括、最多两个关键词、平台可用状态和真实操作入口。

卡片保持稳定高度和按钮基线。悬停时只有聚光边框、图片轻微景深和按钮显现，不使用大幅倾斜。选中卡片有明确边框和 `aria-current`，并同步舞台、导航进度和 URL 状态。

应用、小游戏和工程体验分区保留；三个分区使用不同强调色，但共享同一套卡片结构，便于后续继续增加项目。

### 6. 平台与维护

Windows、macOS、iOS 和网页状态直接落在项目卡和舞台中。原平台总览保留为跨项目下载索引，但降到项目图鉴之后。

维护编辑器继续存在，通过顶部“编辑”入口进入；公开浏览状态下不让维护控件打断项目阅读。现有可编辑文案和本地持久化语义不变。

## 交互与动效

- 首次加载：导航、舞台和首屏卡片按层级交错进入，仅执行一次。
- 项目选择：卡片高亮，舞台内容短时交叉淡入，进度同步更新。
- 筛选与搜索：卡片位置平滑重排，不重放入场。
- 指针反馈：桌面端舞台点阵和主要按钮可轻微磁吸，移动端关闭。
- 键盘：分类、卡片、轮播和主题切换均可使用 Tab、Enter 和方向键操作。
- 减少动效：`prefers-reduced-motion: reduce` 下取消视差、磁吸和位移动画，只保留即时状态变化。

## 数据与实现边界

独立预览使用当前 Hub 的真实项目数据生成预览数据副本，不更改生产数据文件。预览中的外链默认可点击，但不会触发下载；下载入口以平台状态和原 URL 展示。图片优先复用仓库已有截图、海报和图标，没有适合图片时使用基于项目名称与类型生成的排版封面，不伪造产品界面。

预览目录与生产工作树分离，本地服务使用独立端口。只有用户确认预览后，才把经过验证的结构映射回生产 `index.html`、样式和运行时脚本。

## 兼容与错误处理

- 支持 Windows 与 macOS 的当前 Chrome、Edge、Safari 和 Firefox。
- 图片加载失败时显示项目类型封面和可读名称，卡片尺寸不变化。
- 本地存储不可用时主题和选择状态退化为会话内状态，不阻塞浏览。
- 外部链接缺失时按钮显示不可用状态，不产生空链接或 `#` 占位。
- 不在 Windows 本机运行、构建、显示、下载或重新生成 ClickFlow；本地测试明确排除 ClickFlow 套件。

## 预览验收

- 真实 29 个项目数据完整，原顺序和三大分区不丢失。
- 搜索、六类筛选、排序、卡片选中、舞台同步和四套主题可操作。
- 所有可见文字在白色与深色主题下清晰，无小于 12px 的界面文字。
- `1440x900`、`1024x768`、`390x844` 无横向溢出、文字重叠和按钮截断。
- 首次加载动画只执行一次，正常切换和筛选不重新播放。
- 减少动效模式、键盘焦点和图片失败回退可验证。
- 浏览器控制台无脚本错误，关键资源无 404。

## 生产改版门禁

用户必须先查看独立预览并明确确认。确认后再编写生产迁移计划、按 TDD 修改主页、完成 Windows/macOS 浏览器回归、推送 GitHub，并等待 GitHub Pages 对精确提交部署成功后进行公网验收。
