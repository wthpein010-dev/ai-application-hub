# Paws 公开编辑器本地关卡导入设计

## 目标

在已发布的“关卡3D编辑器”中增加明确的“导入 JSON”入口。用户主动选择本机关卡文件后，网页读取、校验并打开该关卡，使其可以继续 2D/3D 编辑和试玩。

导入完全发生在浏览器中：文件不会上传服务器，网页也不会获得目录权限或读取用户未选择的文件。

## 方案选择

采用一次性 `<input type="file">` 导入：

- 兼容主流桌面浏览器；
- 权限只覆盖用户本次选择的文件；
- 可复用现有浏览器存储、关卡列表、编辑、试玩和保存流程；
- 不依赖 Chromium 专属的 File System Access API。

本轮不增加持久文件句柄、原文件回写或拖拽区域。它们会扩大权限、兼容性和交互范围，不是“打开本地关卡”的必要条件。

## 用户交互

1. 关卡库操作区增加“导入 JSON”按钮和隐藏文件输入框。
2. 按钮只在桌面编辑模式显示；390px/粗指针只读模式继续只允许查看与试玩。
3. 当前关卡有未保存修改时，导入前沿用现有确认交互，避免误丢编辑状态。
4. 文件选择器只接受 `.json`。
5. 导入成功后：
   - 关卡保存为当前浏览器的本地副本；
   - 关卡列表立即刷新并选中新关卡；
   - 编辑器打开导入内容，可切换 2D/3D 和试玩；
   - Toast 明确显示浏览器中的实际副本文件名。
6. 页面提示补充“本地 JSON 仅在当前浏览器读取和保存，不会上传”。

## 数据与命名

- 文件名必须通过现有 `isValidLevelFileName` 规则。
- 文件大小上限为 5 MiB；空文件、读取失败、JSON 解析失败和结构解析失败均拒绝导入。
- 原文件名未占用时直接使用。
- 若与内置关卡或浏览器本地关卡重名，依次生成：
  - `<base>_import.json`
  - `<base>_import_2.json`
  - `<base>_import_3.json`
- 导入永不覆盖已有记录。
- 导入内容先经过现有 `parseLevelDocument`，再用 `serializeLevelDocument` 写入浏览器存储，从而保留未知字段并同步 `designerNote.levelData`。
- 导入产生的记录标记为本地关卡，刷新页面后仍可从关卡列表打开。

## 组件边界

新增纯函数模块 `ui/local-level-import.mjs`：

- 校验文件元数据和大小；
- 读取并解析 JSON；
- 生成无冲突的导入文件名；
- 返回标准化的导入负载或用户可读错误。

`WorkbenchController` 只负责：

- 触发文件选择器；
- 处理未保存修改确认；
- 调用导入模块和现有静态 API；
- 刷新列表并打开导入关卡；
- 将错误显示为 Toast。

静态 API 不新增上传能力；继续使用 `saveLevel({ saveAs: true })` 将副本写入 `localStorage`。

## 错误处理

- 非 `.json` 或不安全文件名：提示“请选择文件名合法的 .json 关卡文件”。
- 空文件：提示“关卡文件为空”。
- 超过 5 MiB：提示“关卡文件超过 5 MiB”。
- JSON 损坏：提示“关卡文件不是有效 JSON”。
- 关卡结构无法解析：显示适配器返回的安全错误信息。
- 浏览器存储失败或空间不足：沿用静态 API 的用户可读错误。
- 任一失败都不改变当前已打开关卡，也不写入本地存储。

## 测试与验收

- 单元测试：
  - 合法 Unicode `.json`；
  - 非 JSON、空文件、超限、坏 JSON；
  - 原名未占用；
  - `_import` 和递增后缀重名处理；
  - 未知字段经适配器往返保留。
- 控制器契约测试：
  - 页面存在按钮与文件输入；
  - 控制器绑定选择事件；
  - 只读模式不触发导入；
  - 导入使用 `saveAs: true` 且成功后刷新并打开。
- 浏览器测试：
  - 选择内存中的本地 JSON；
  - 列表从 1 项增加到 2 项；
  - 导入关卡立即打开；
  - `localStorage` 产生本地记录；
  - 刷新后导入关卡仍存在；
  - 同名导入生成安全副本；
  - 390px 导入按钮不可见；
  - 控制台、HTTP、页面和请求错误均为 0。

## 发布边界

公开仓库只增加导入能力和合成测试数据，不提交用户真实关卡。发布仍通过 `origin/main` 和 GitHub Pages，线上验收需使用文件选择器真实导入一份临时示例 JSON。
