# AI Application Hub 动态作品展馆主页设计规格

日期：2026-08-26

状态：A“动态作品展馆”方向已确认，待用户复核书面规格

适用范围：AI Application Hub 生产主页视觉与交互改版；不改动各子项目功能、平台安装包和统一子页模板

## 目标

把当前以文字卡片为主的首页升级为“动态作品展馆”：真实项目截图、海报和视频画面成为主要视觉，项目名称、用途、平台状态和访问入口与图片共同构成浏览路径。新版必须比当前页面更丰富、更有互动感，同时继续让用户快速扫描全部应用、小游戏和工程体验，而不是变成只有少数重点作品可见的营销页面。

成功标准：

- 用户进入首屏即可看到真实项目画面、当前精选项目信息和明确入口，不出现大面积空白。
- 全部现有项目、三大集合、原始顺序、六类应用工具页签和真实链接均保留。
- 每个可见项目都有与自身内容匹配的真实媒体或明确的专属回退视觉，不复用无关通用图片。
- 卡片选择、精选舞台、导航进度和 URL 状态同步；普通切换不重放整页入场动画。
- 默认主题是干净白色，桌面与移动端都具备足够文字尺寸、对比度和稳定布局。

## 已确认方向

采用独立预览 `design-previews/hub-template-directions-v2/` 中的 A“动态作品展馆”作为视觉基准：左侧为简洁项目叙述和入口，右侧为主导首屏的真实媒体；下方使用不对称图文网格形成展馆节奏。B“横向故事画廊”和 C“可拖拽应用桌面”不作为生产骨架，避免 29 个项目的扫描效率下降或手机端交互变复杂。

生产版不会逐字复制方向预览中的演示文案或六项样例数据，而是接入现有 Hub 的真实数据、编辑状态、平台入口和三大集合。

## 视觉系统

- 默认“清透白”使用接近白色的页面背景、深墨色正文、珊瑚红主强调、青绿色辅助强调和黄色选中标记，避免单一蓝色或紫色页面。
- 保留清透白、雾蓝、珊瑚、深夜四套主题和当前本地持久化语义；项目媒体不整体染色，主题只影响页面表面、文字、边框、按钮和遮罩对比度。
- 卡片圆角不超过 8px；主要层级由图片尺寸、网格跨度、边框和留白建立，不叠加多层卡片或装饰光球。
- 标题按容器设置固定断点，不使用随视口无限放大的字体。正文不低于 13px，辅助标签和按钮不低于 12px。
- 图片必须清晰显示实际界面、游戏画面、产出示例或与应用直接相关的素材；不得使用重复文字封面冒充产品截图。

## 页面结构

### 1. 顶部导航

保留站点名称、总览、应用、小游戏、工程体验、主题和编辑入口。桌面端导航保持单行；平板和手机将集合入口压缩为可横向滚动的稳定页签，不隐藏核心入口。

搜索不单独占据首屏，可从展馆筛选轨道进入。编辑入口继续打开现有右侧维护面板，不在公开浏览状态显示密集编辑图标。

### 2. 精选项目舞台

首屏采用方向 A 的非对称双栏结构：

- 左侧显示项目类别、名称、一段扩展摘要、最多两个平台状态和主要操作入口。
- 右侧使用约 60% 首屏宽度展示真实媒体；图片使用稳定比例和 `object-fit`，不因不同项目尺寸造成舞台跳动。
- 图片底部显示序号、项目名和一句不与左侧摘要重复的说明；进度条不重复项目名称。
- 上一个和下一个按钮使用足够大的居中箭头，位于舞台媒体边缘，不遮挡文字。

轮播顺序继续严格遵循：应用项目集合从左到右、从上到下，之后是小游戏体验集合，再之后是工程体验，最后循环回第一个应用。点击下方项目卡时选中状态和舞台同步；点击卡片操作按钮只执行对应操作，不改变或重播整个列表。

### 3. 展馆筛选轨道

舞台之后设置一条紧凑的筛选轨道，包含搜索、六类应用工具页签和当前结果数量。六类名称固定为：插件工具、辅助工具、生活工具、网页情报、桌面工具、内容工具。

小游戏和工程体验使用各自集合入口，不混进六类应用页签。筛选只影响应用集合；搜索可匹配全部集合中的项目名称、简介、场景和关键词。清空搜索恢复生产原顺序。

### 4. 应用项目集合

桌面基线为四列，但不使用完全相同的目录卡：拥有高质量横向媒体的项目可跨两列，内容型或竖向媒体项目可在指定位置跨两行，其余项目使用标准卡。跨度由明确的媒体清单决定，不在每次加载时随机变化，避免布局跳动和顺序混乱。

每张卡片包含：

- 与项目匹配的图片；
- 六类工具标签之一；
- 项目名称和一段精简概括；
- 平台可用状态；
- 按真实数据出现的 `网页预览 / 介绍视频 / Wins下载 / Mac下载 / iOS安装`。

卡片按钮大小统一并底部对齐。普通卡片只展示实际存在的入口，不出现空链接和占位下载。选中卡片使用黄色内边框和 `aria-current`，图片仅做轻微平移或放大。

### 5. 小游戏体验集合与工程体验

小游戏和工程体验继续使用独立标题、数量和固定顺序。它们共享应用卡片的媒体、标题、摘要和按钮结构，但使用各自的识别色：小游戏为橙色，工程体验为蓝绿色。

每个集合都采用可扩展的四列图文网格，不恢复单个超长横条。项目增多后按生产顺序自然换行；特殊大卡只用于有足够清晰媒体且确实需要强调的项目。

### 6. 编辑与维护

现有右侧维护面板、可编辑文案、本地存储、Markdown 导出和项目字段继续工作。新版新增媒体字段的维护入口只允许选择仓库内相对路径或经过验证的公网资源；无媒体时使用项目专属回退封面。

同一区域继续共用一个编辑入口，不恢复每段文案旁边的大量编辑按钮。用户已经在线修改的文本按当前固化数据和本地覆盖规则迁移，不能被默认文案覆盖。

## 媒体资源策略

### 优先级

1. 复用项目已有的界面截图、海报、教程视频帧和真实内容样例。
2. 对公开网页自动截取清晰、无弹窗、能说明功能的状态画面。
3. 只有前两项都不可用时，才为该项目制作专属插图或排版封面。

不得把同一张通用 AI 背景分配给多个无关项目。人物照片、游戏画面和应用截图只能用于其所属项目。媒体清单记录来源路径、所属项目、焦点位置和替代文本，便于后续更换。

### 性能

- 首屏舞台媒体使用响应式 WebP/AVIF 候选和原格式回退，明确 `width`、`height` 或 `aspect-ratio`。
- 首屏当前图片优先加载；下一张只预取缩略图；首屏以下图片统一懒加载。
- 大图生成适合卡片的缩略版本，不直接把数兆像素原图用于四列卡片。
- 图片失败时显示项目专属回退视觉和可读名称，卡片尺寸不变化。

## 交互与动效

- 首次进入：顶部导航、舞台文字、舞台图片和首屏卡片按层级进入，仅执行一次。
- 项目选择：舞台图片短时交叉淡入，文字以不超过 12px 的短距离移动；选中卡片边框和进度同步。
- 卡片悬停：图片轻微平移或放大、按钮和平台状态提高对比度；不使用大角度旋转。
- 精细指针：舞台图片可使用最大约 3 度的轻微景深响应；触屏和减少动效模式关闭。
- 筛选与搜索：项目在原容器内重排，不重放首屏入场。
- 主题切换：颜色平滑变化，图片保持原色；刷新后保持用户选择。
- `prefers-reduced-motion: reduce` 下取消视差、磁吸、位移和交错入场，只保留即时状态切换。

## 数据与状态

生产运行时继续以当前项目数据为权威来源，不维护第二套手写项目清单。新增媒体清单按项目 `id` 关联，不复制名称、简介或入口数据。

状态至少包括：当前项目、应用分类、搜索词、主题、是否完成首次入场和编辑面板状态。项目选择写入现有 URL/hash 语义与本地选择状态；刷新后恢复当前项目，但不恢复正在播放的动画。

Windows 本地开发必须在渲染前排除 `clickflow`，DOM、图片和请求中都不得出现 ClickFlow；数据完整性测试可以读取其静态记录，但不得运行、构建、显示、下载或重新生成。远端 CI 继续承担完整生产页面的 ClickFlow 验证。

## 兼容与无障碍

- 支持 Windows 当前 Chrome、Edge、Firefox，以及 macOS 当前 Chrome、Safari、Firefox。
- 桌面约 1440px 使用四列基线；约 1024px 使用两至三列自适应布局；390px 手机使用单列并取消跨列跨度。
- 所有交互可使用键盘，分类按钮提供 `aria-pressed`，选中项目提供 `aria-current`，图片使用项目语义替代文本。
- 触控按钮最小可点区域约 40px；文本、按钮和平台标签不截断关键名称。
- 图片失败、本地存储不可用和链接缺失都必须可退化，不阻塞其他项目浏览。

## 实现边界

本次修改只涉及主页 HTML、主页 CSS、主页运行时、媒体清单与缩略资源、对应测试和缓存版本。各项目子页、统一返回主页按钮、视频播放器、Windows/macOS/iOS 安装包和项目源码不在本次改版范围内。

不引入 React、Three.js 或大型动画框架。当前主页是静态 HTML/CSS/JavaScript，使用浏览器原生能力即可实现所需效果，避免增加 GitHub Pages 首屏负担。

## 验收门禁

- 全部生产项目、原顺序、三大集合、六类应用页签和真实操作链接不丢失。
- 除本机禁止显示的 ClickFlow 外，每个本地可见项目都有正确媒体或专属回退视觉；无跨项目错配图片。
- 卡片点击与舞台、导航进度、选中样式和 URL 同步；应用到小游戏再到工程体验的循环顺序正确。
- 首次入场只播放一次；选择、筛选、搜索和主题切换不重播整页动画。
- 清透白、雾蓝、珊瑚和深夜四主题文字清晰，界面文字不小于 12px，正文不小于 13px。
- `1440×900`、`1024×768`、`390×844` 无横向溢出、重叠、按钮截断和不可见操作。
- 键盘、触屏、减少动效、图片失败、本地存储失败和无效链接回退通过验证。
- 本机聚焦测试明确排除 ClickFlow；远端完整测试、GitHub Pages 部署和公网真实浏览器验收对同一精确提交成功。

## 发布流程

书面规格经用户复核后，先编写实施计划并按 TDD 在隔离工作树迁移生产主页。完成本地桌面、平板和手机验收后，再提交和推送 GitHub；等待 Pages 对精确提交部署成功，最后逐项验证公网主页、媒体、链接、主题和响应式行为。发布前线上主页保持当前版本。
