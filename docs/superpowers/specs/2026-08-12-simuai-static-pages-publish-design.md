# SimuAI 静态公开版优化与发布设计

日期：2026-08-12  
状态：用户已确认方案，待书面规格复核  
发布目标：AI Application Hub 工程体验区与 GitHub Pages

## 1. 目标与原则

本次工作将 SimuAI 万物实验室从已完成的本地原型整理为稳定、诚实、可公开使用的 GitHub Pages 工程体验。重点修复“点击搜索没有反应”的体验，并完成 Hub 卡片、演示页、教学视频、桌面与手机验收。

公开版的核心承诺是：输入问题后，从 12 个受控实验中进行本地匹配，并清楚展示匹配结果、计算依据和能力边界。公开版不宣称正在调用远程模型，也不依赖 GitHub Pages 无法运行的 Node 服务。

## 2. 能力边界

### 2.1 GitHub Pages 公开版

- 只执行浏览器内的模板匹配、六类确定性模型计算和 SVG 渲染。
- 不请求 `/api/compile`，不要求用户提供 API Key，不向浏览器存储写入凭据。
- 页面明确展示“公开版从 12 个受控实验中匹配；当前未连接远程 AI”。
- 拖动参数始终在本地重算，不产生网络请求。

### 2.2 本地 Node 可选版

- 保留现有同源 `/api/compile` 代理及其安全校验，供开发者在本地显式配置后使用。
- 本地 AI 编译能力不影响公开版启动，不作为 Hub 卡片文案或公开视频的默认承诺。
- 运行说明分别描述静态公开版与本地代理版，避免用户误以为 Pages 能托管密钥或服务端逻辑。

## 3. 搜索交互

### 3.1 状态流

搜索表单使用四个可观察状态：`idle`、`matching`、`matched`、`recommended`。异常状态单独使用 `error`，但本地匹配自身不依赖网络，正常输入不应进入该状态。

1. 用户提交问题后，按钮进入短暂的“正在匹配实验库”状态并禁用，防止重复提交。
2. 匹配器返回标准化问题、候选实验、分数和命中的关键词。
3. 高匹配结果立即加载对应实验，结果条展示实验名称、命中原因和“已打开实验”；页面滚动到实验舞台并播放一次可减少动态效果的高亮动画。
4. 低匹配结果不改变当前实验，紧邻输入框展示三个按相关度排序的推荐卡片。每张卡片包含实验名称、适用问题和“打开实验”操作。
5. 完成后按钮恢复，结果区通过 `aria-live` 报告结果数量和当前动作，输入内容保持不变。

### 3.2 空输入与重复搜索

- 空输入不提交，输入框获得焦点并显示可执行提示。
- 同一问题重复提交仍重新展示结果反馈和舞台高亮，不让用户误以为点击失效。
- 通过模板卡或推荐卡打开实验时，结果区同步标明来源，不冒充自然语言搜索命中。
- 所有搜索结果文本均使用文本节点渲染，不使用用户输入拼接 HTML。

### 3.3 结果文案

- 高匹配：`已从 12 个实验中匹配到「实验名」`，附命中关键词或问题类型。
- 低匹配：`没有完全对应的实验，以下 3 个最接近`。
- 能力提示：`公开版使用本地受控实验库，不会把输入发送给远程 AI。`

## 4. 页面视觉与信息架构

### 4.1 首屏

- 保留深蓝、青绿、紫色的实验室视觉，提升输入区与主按钮的层级和对比度。
- 将问题输入、示例问题和静态能力提示组成首屏主操作区。
- 搜索结果紧跟输入区出现，确保桌面与手机都无需猜测按钮是否生效。
- 顶部固定提供统一的“返回主页”按钮，目标为 `../../index.html#engineering`。

### 4.2 实验舞台

- 新增来源徽章：`内置实验`、`搜索匹配`或`推荐打开`。
- 实验切换后标题区、指标区和图表统一刷新；舞台短暂高亮，并将焦点移到舞台标题以服务键盘与读屏用户。
- 保留指标、SVG 图表、参数控件、公式、假设、边界和免责声明。
- 手机按“结论与指标 → 图表 → 参数 → 解释”的顺序单列展示，图表自身可安全滚动但页面不得横向溢出。

### 4.3 动效与可访问性

- 搜索按钮、结果卡、舞台切换使用 160–320ms 的轻量过渡。
- 遵守 `prefers-reduced-motion`，关闭滚动动画和高亮位移。
- 输入、按钮、推荐卡、滑块、数值输入和解释面板均支持键盘操作与清晰焦点样式。
- 状态不只依赖颜色表达；按钮文字、状态文案和来源徽章共同说明结果。

## 5. 模块与数据流

### 5.1 模块职责

- `matcher`：标准化输入，计算 12 个模板的关键词分数，返回稳定排序的候选及命中证据。
- `resolver`：根据明确的运行能力配置选择静态或本地代理流程；公开构建直接走静态流程，不通过失败请求探测代理。
- `app`：管理搜索状态、结果渲染、实验激活、焦点和舞台高亮。
- `templates / engines / presenter / chart`：继续负责受控实验数据、计算、展示模型和 SVG 输出，不扩大 DSL。

### 5.2 数据流

`问题输入 → 本地标准化与评分 → 高匹配直接激活 / 低匹配三项推荐 → 用户选择实验 → 本地模型计算 → 指标、图表、结论与解释同步渲染`

公开路径上没有网络编译分支。开发者本地显式启用代理时，才允许未命中问题进入既有的受约束编译器流程。

## 6. Hub 与视频接入

### 6.1 工程体验卡片

- ID：`simuai`
- 名称：`SimuAI 万物实验室`
- 状态：`engineering`
- 卡片追加在现有工程体验集合末尾，不改变其他项目顺序。
- 只展示“演示”和“视频”两个按钮，不展示空下载入口。
- 简介明确为“自然语言匹配受控实验、拖动参数观察模型结果”，不宣称任意问题在线生成。
- 为已有浏览器本地存储增加精准迁移，保证旧访客能获得本次正式卡片内容，同时不覆盖用户真正自定义的其他项目。

### 6.2 教学视频

- 使用当前页面真实录制一段不超过 4 分钟的 H.264 MP4，目标分辨率 `1280×720`。
- 内容覆盖：输入问题、看到明确搜索反馈、切换实验、拖动参数、查看图表与计算依据、理解静态公开版边界。
- 配套海报、教程脚本和简体中文字幕 VTT；任一时刻字幕仅一行，不重叠、不越出安全区。
- 视频页复用 Hub 统一播放器、延迟加载和固定返回主页按钮，返回 `../../../index.html#engineering`。

## 7. 错误与降级处理

- 页面必须通过 HTTP(S) 访问；README 明确说明不能把模块化应用当作普通 `file://` 页面验收。
- 若核心模块加载失败，静态 HTML 中保留可见的启动提示；浏览器测试把脚本、样式或媒体 404 视为失败。
- 非有限计算结果不覆盖上一组有效结果，并提示用户调整参数。
- 推荐数量不足时显示实际数量，不制造空卡片。
- 视频加载失败时使用统一播放器的重试提示，不影响演示入口。

## 8. 测试与发布门禁

### 8.1 自动测试

- 匹配器覆盖高匹配、低匹配、空输入、同分稳定排序和命中证据。
- resolver 断言 Pages 静态模式对任意问题都不调用 `/api/compile`；本地代理模式保持原有安全测试。
- 页面契约覆盖状态文案、结果区、`aria-live`、返回 Hub、来源徽章和推荐操作。
- Hub 测试覆盖唯一卡片、工程区末尾、演示/视频按钮、旧存储迁移和项目总数。
- 视频测试覆盖统一播放器、H.264、分辨率、时长、VTT 单行字幕和文件存在性。

### 8.2 真实浏览器验收

- 桌面 `1440×900` 与手机 `390×844` 完成高匹配、低匹配推荐、实验打开、参数拖动和解释面板流程。
- 验证搜索过程中网络请求列表不包含 `/api/compile`。
- 页面、图表和视频无横向溢出、文字重叠、控制台错误、页面异常、失败请求或资源 404。
- 视频真实点击播放并推进，字幕轨为显示状态。

### 8.3 发布验收

- 从最新 `origin/main` 创建干净发布分支，移植 SimuAI 变更并保留远端新增内容。
- 现场确认 GitHub 身份和仓库写权限，普通推送并通过 PR 合并到 `main`，不得强推。
- 等待针对最终提交的测试与 GitHub Pages 工作流成功。
- 公网逐项验证 Hub 工程区卡片、演示页、搜索完整流程、视频页、MP4/VTT、返回主页链接和移动端布局。
- 只有公网内容与最终提交一致且上述门禁通过后，才报告发布完成。

## 9. 明确不做

- 不在 GitHub Pages 中运行 Node 服务、代理模型请求或保存服务端密钥。
- 不要求公开用户输入自己的 API Key。
- 不扩大当前六类模型和 12 个实验，不加入账号、云存储、支付或社区。
- 不用加载动画或模糊文案伪装真实 AI 调用。

## 10. 完成标准

用户在公开 GitHub Pages 上点击搜索后，必须立即获得可感知、可复现且与真实能力一致的反馈；高匹配问题能进入对应实验，低匹配问题能选择三个明确推荐，整个流程不依赖远程后端。Hub 工程体验卡片、演示、教学视频和返回路径完整可用，并通过自动测试、桌面/手机浏览器、GitHub 工作流与公网逐链接验收。
