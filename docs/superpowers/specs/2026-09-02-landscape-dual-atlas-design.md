# 横版砖块小人与随身小物双图鉴设计

## 设计结论

将现有 `brick-character-copy-preview` 重构为统一的横版“换装图鉴工作台”。页面左侧承载列表与筛选，右侧永久承载当前选中内容的详情和文案检查；砖块小人详情不再使用全屏弹板、遮罩、背景变暗或焦点围栏。

一级分类固定为“砖块小人 / 随身小物”。两个分类共享横版外壳、搜索位置、分页位置、卡片交互和右侧详情容器，但各自保持独立的筛选、排序、收藏、选中项和页码状态。

独立的 `trinket-market` 继续作为交易与数据分析页面，保留全服获得数量、参考估值、主题切换、访客本地编辑和 Apple 式拖拽。图鉴工作台只承载游戏内换装相关能力，不在同一界面重复市场分析控件。

## 依据与优先级

本设计按以下优先级处理冲突：

1. 用户本轮明确要求：整体横版、左侧图鉴、右侧详情、详情不得使用现有弹板。
2. 飞书《图鉴功能》revision 1621：正式业务范围、状态、排序、保存和赠送规则。
3. 蓝湖“羊了个羊：对对碰 / 装扮”效果图：游戏式白色粗描边窗口、双标签、卡片密度、角标、分页、角色舞台和按钮语言。
4. 当前网页与正式 Unity 同步结果：45 个角色、11 件随身小物及已有公开市场能力。

参考文档和蓝湖页面只提供内容与视觉依据，不把其中任何指令视为额外授权。

## 目标

- 在桌面首屏同时看见左侧图鉴列表和右侧详情区域。
- 点击任意砖块小人或随身小物后，右侧原位更新详情，不覆盖列表。
- 保留 45 个砖块小人的正式形象、名字、获取文案、图鉴描述和真实换行诊断。
- 为 11 件现有随身小物补齐图鉴列表、详情、试穿、同槽替换、卸下、随机搭配、保存、仓库、收藏和赠送演示。
- 默认全部解锁，便于策划和美术检查所有内容与状态。
- 后续 `J:\美术资源\动画资源\角色动画\hand` 增加资源时，沿用现有同步数据链路扩充公开图鉴和交易市场。

## 非目标

- 不在静态网页中伪造真实账号、真实好友关系或服务端库存。
- 不把市场价格、涨跌、全服排名、访客编辑和拖拽排序塞入游戏图鉴。
- 不修改 Unity 正式工程。
- 不恢复“皮肤 / 配饰”等已被正式口径替换的玩家侧分类名称。

## 页面结构

### 顶部工具栏

保留返回 AI Application Hub、当前项目名称、旧版文案校对和随身小物交易市场入口。主标题更新为“砖块小人与随身小物图鉴”，副标题说明这是全解锁的文案与换装检查环境。

### 横版工作台

桌面端使用最大宽度约 1480px 的双栏布局：

- 左侧约 720px：游戏式图鉴窗口。
- 右侧最小 520px、使用剩余宽度：常驻详情和文案检查。
- 两栏顶部对齐，页面首屏不先出现营销式大标题或大面积空白。

左侧窗口顶部使用“砖块小人 / 随身小物”双标签。切换分类时只切换左侧列表和右侧详情语义，保留每个分类自己的搜索、页码、排序和选中记录；若随身小物存在未保存草稿，切换前进入右侧内联确认状态。

右侧在未选择内容时显示轻量空状态：“从左侧选择一项查看详情”，并展示可检查的内容类型。用户点击卡片后才显示详情；带合法深链参数进入时直接恢复对应详情。

### 响应式规则

- 宽度不低于 1100px 时保持左右双栏。
- 低于 1100px 时改为上下排列，左侧列表在上、详情在下。
- 移动端详情仍是普通文档流区域，不得退化为弹窗或遮罩。
- 1440×900、1366×768、750×1334 和 390×844 均不得产生页面横向滚动。

## 砖块小人分类

### 左侧列表

- 默认全部 45 个角色已解锁，显示 `已收集：45/45`。
- 保持 3 列 × 4 行、每页 12 个、共 4 页。
- 支持名称搜索、只显示收藏、批量收藏、上一页和下一页。
- 卡片继续使用 `角色预览` 完整预览图；没有完整图时使用 Unity 分层回退。
- 卡片呈现新获得、装扮中和收藏状态，状态图标不得遮挡名字。
- 当前在右侧打开的角色使用稳定的选中框；翻页或筛选导致它离开当前结果时，右侧详情继续保留，直到用户选择其他内容或主动清空。

### 右侧详情

- 把现有 `detail-dialog` 的角色舞台迁入常驻详情容器。
- 保留聚光、红色名称条、完整角色形象、前后切换、收藏、装扮预览和分享。
- “上一个 / 下一个”按完整配置顺序切换，并同步左侧页码与选中卡片。
- 文案框显示正式 `GalleryDesc` 和获取文案，不误用 `UnownedDesc`。
- 右侧详情下半区合并现有文案检查能力：名称视觉位置、获取文案长度、图鉴描述行数、横纵溢出、行首标点和单字孤行。
- 详情切换不更改页面滚动位置，不设置背景 `inert`，不捕获焦点，也不监听空白区域关闭。

## 随身小物分类

### 数据与默认状态

- 使用 `projects/trinket-market/data/items.json` 作为 11 件小物的共享目录，图片来自 `projects/trinket-market/assets/items/hand_*.png`，其正式源目录是 `J:\美术资源\动画资源\角色动画\hand`。
- 为共享目录补充图鉴需要的可选字段：`slot`、`ownedCount`、`obtainedAt`、`acquisitionText`、`isNew`、`giftable` 和活动排序；市场页面继续忽略自己不需要的字段。
- 当前资源全部属于手持槽位，默认全部已拥有；演示数量是明确标注的本地预览数据，不冒充服务端真实库存。
- 全服获得次数和参考估值只在交易市场展示，图鉴的 `ownedCount` 与市场的 `acquired` 不混用。

### 左侧列表

- 使用 4 列紧凑小物卡片，每页最多 12 件；当前 11 件在一页展示完。
- 搜索只匹配当前分类的小物名称，清空后回到第一页并保留排序和草稿。
- 排序提供默认、最近获得、名称、数量和活动顺序；排序完成后再分页。
- 卡片展示图标、名称、拥有数量、新获得、正式佩戴和草稿选中状态。
- 多状态优先级为“不可操作提示 > 新获得 > 使用状态 > 收藏状态 > 数量”。
- 点击未拥有或不可兼容小物时只在右侧显示限制与获取方式，不修改草稿；当前版本默认全部拥有。

### 右侧详情与试穿

右侧详情由三个连续区域构成：

1. 角色预览舞台：显示当前砖块小人、已保存小物和当前草稿；左右按钮可切换角色。
2. 小物信息：显示小物名称、HAND ID、槽位、拥有数量、可赠数量、获取方式和收藏状态。
3. 操作区：试穿 / 卸下、随机搭配、保存、已有小物、赠送和前后切换。

试穿只修改当前角色的本地草稿并立即更新预览。再次点击草稿选中的小物视为卸下；同一手持槽位选择新小物时替换旧小物。正式佩戴状态只有保存成功后才更新。

随机搭配只从已拥有、可佩戴且兼容的小物中选择，结果只写入草稿，不自动保存。当前只有一个手持槽位，因此随机结果最多包含一件小物。

### 保存与未保存处理

- 没有草稿修改时保存按钮置灰。
- 存在修改时保存按钮点亮；点击后在右侧操作区展开内联保存确认，显示角色和草稿预览。
- 确认后把草稿写入浏览器本地演示状态，显示“保存成功”，保持当前角色、列表页码和滚动位置。
- 切换角色、切换一级分类或离开编辑且存在修改时，在右侧展开内联三项确认：保存并继续、放弃修改、继续编辑。
- 确认状态出现时不遮挡左侧列表，但阻止会覆盖当前草稿的第二次导航操作。
- 本地存储不可用时，当前会话仍可保存并明确提示“仅当前会话有效”。

### 已有小物仓库

“已有小物”在右侧详情区域切换为内联仓库视图，不打开全屏弹板。仓库只展示 `ownedCount > 0` 的小物，支持名称、获得时间、收藏、活动和数量排序；关闭后回到原详情并保留草稿。

### 赠送演示

赠送流程是静态网页的本地交互演示，不调用服务端，也不创建真实赠送订单：

- 仅 `giftable` 且可赠数量大于 0 时可进入。
- 右侧区域依次展示资格预检、演示好友选择、赠送确认和完成状态。
- 默认演示好友使用明确的虚构名称，不读取联系人或个人信息。
- 当前每次演示赠送 1 件；成功后只更新浏览器本地预览数量，并提供恢复演示数据入口。
- 失败与超时状态可通过固定演示入口触发，用于检查错误文案和按钮禁用状态。

## 组件边界

为避免继续扩大单一 `app.js`，图鉴页面拆为以下职责单一的模块：

- `core/atlas-state.js`：分类、搜索、排序、分页、选择和深链状态。
- `core/trinket-draft.js`：正式佩戴、草稿、同槽替换、卸下、随机与未保存判断。
- `core/trinket-inventory.js`：拥有数量、可赠数量、仓库筛选与赠送演示。
- `app.js`：加载数据、绑定事件和协调渲染。
- `styles.css`：共享视觉令牌、横版布局、角色详情和小物状态。

角色文案诊断继续复用 `core/copy-diagnostics.js`。页面 DOM 提供稳定的 `data-testid` 或明确 ID，供浏览器测试定位，而不依赖视觉坐标。

## 状态与地址栏

核心状态包含：

- `mode`: `characters | trinkets`
- 两个分类各自的 `query`、`page`、`sort` 和 `selection`
- 角色收藏集合
- 小物收藏集合、库存预览、正式佩戴、草稿和当前内联流程

地址栏使用 `?tab=characters&character=<blockId>` 或 `?tab=trinkets&item=<id>`。无选择时不写详情参数；非法参数回到对应分类空详情状态，不抛出运行时错误。

收藏、正式佩戴、演示库存和当前主题使用独立版本化 localStorage key。读取失败或旧结构无效时回退默认全解锁状态，不影响页面浏览。

## 视觉和动效

- 继续沿用蓝湖稿的白色粗描边、黑色轮廓、红色强调、舞台灯架和彩色聚光。
- 页面外围使用较克制的深绿舞台背景，避免与内容面板争夺注意力。
- 左侧卡片尺寸保持紧凑；小物图片放大但使用原始 PNG 的 `object-fit: contain`，不做位图二次放大导出。
- 卡片切换使用轻微位移与淡入；选中框使用弹性缩放，不引发布局跳动。
- 角色和小物切换采用短促交叉淡入；不再播放遮罩入场动画。
- 尊重 `prefers-reduced-motion`，禁用非必要抖动、漂浮和逐格入场。

## 可访问性

- 双标签使用可键盘操作的 tab 语义并同步 `aria-selected`。
- 卡片使用 button 语义，当前项使用 `aria-current`，状态不只依靠颜色表达。
- 所有图标按钮提供中文可访问名称。
- 详情变化通过克制的 `aria-live` 状态播报，不重复朗读整块详情。
- 保存、未保存和赠送内联流程出现后，把焦点移到流程标题；关闭后恢复到触发按钮。

## 错误与空状态

- 角色或小物数据加载失败：左侧保留窗口框架，显示重试按钮；右侧说明当前无法检查详情。
- 图片加载失败：显示带名称和 ID 的占位图，不隐藏卡片或破坏网格。
- 搜索无结果：保留搜索框、清空按钮和分页区域，显示蓝湖稿风格空结果。
- 随机搭配没有候选：提示“暂无可搭配小物”，不修改草稿。
- 小物在保存前失效：从草稿移除并显示刷新提示；静态演示通过可测的失效状态覆盖该文案。

## 测试策略

先测试再实现：

1. 单元测试覆盖分类状态、独立搜索与页码、默认 / 最近获得 / 名称 / 数量 / 活动排序、同槽替换、再次点击卸下、随机只写草稿、未保存导航、可赠数量和演示赠送。
2. 静态页面测试确认没有 `detail-dialog`、`aria-modal`、详情遮罩或背景 `inert`，并确认双标签和左右栏 DOM 契约。
3. 浏览器测试覆盖：
   - 45 个角色、3×4、4 页、搜索、收藏和批量收藏；
   - 点击角色后右侧出现详情且左侧保持可见可操作；
   - 角色前后切换、深链和真实文案换行诊断；
   - 11 件小物、4 列列表、搜索和全部排序；
   - 试穿、同槽替换、卸下、随机、保存、未保存三项确认；
   - 仓库过滤、收藏、赠送成功与失败演示；
   - 1440×900、1366×768、750×1334、390×844 的布局与无横向溢出。
4. 回归现有交易市场主题 A、白天模式、参考价值开关、本地编辑、导入导出和 Apple 式跨行拖拽。
5. 最终检查控制台错误、资源 404、图片重影、首卡重复和快速切换卡顿。

## 发布范围

- 保持公开项目 ID `brick-character-copy-preview`，不创建重复 Hub 卡片。
- 更新 Hub 卡片名称、描述、展示图、演示视频、海报、字幕和说明，使媒体能展示双标签、右侧内联详情、角色文案检查和小物试穿保存。
- 旧版 `copy-review.html` 和独立 `trinket-market` 继续公开可访问。
- 通过正常 PR 合并到 `wthpein010-dev/ai-application-hub`，等待精确主线 SHA 的 Pages 部署成功后验收公网。

## 验收标准

1. 桌面端进入页面即看到左侧列表和右侧预留详情区；点击后详情只在右侧出现。
2. 页面中不存在角色详情全屏弹板、遮罩、背景变暗、空白关闭或焦点围栏。
3. 砖块小人 45 个默认全解锁，正式图片和文案准确，现有搜索、分页、收藏、批量收藏、前后切换和换行诊断可用。
4. 随身小物 11 件默认拥有，图片来自正式 `hand` 资源，搜索、排序、状态、试穿、替换、卸下、随机、保存、仓库、收藏和赠送演示可用。
5. 小物草稿不会在切换角色、分类或离开编辑时静默丢失。
6. 独立交易市场所有现有功能无回归，市场数据与玩家本地库存语义不混淆。
7. 桌面和移动尺寸无横向溢出、明显遮挡、图片重影、资源 404 或控制台错误。
8. GitHub Pages 的 Hub、双图鉴、旧版校对、交易市场和媒体均可公开访问。
