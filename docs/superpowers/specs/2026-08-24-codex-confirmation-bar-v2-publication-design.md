# Codex 待确认悬浮助手 v2.0.0 公开发布设计

## 背景

现有 `codex-thread-workbench` 已在 AI Application Hub 发布 v1.3.0 的多会话工作台演示、视频、Windows 下载和 macOS 双架构下载。本机产品已经演进为 v2.0.0「Codex 待确认悬浮助手」：常驻扫描需要用户确认的 Codex 任务，无任务时收进屏幕顶部，有任务或扫描异常时自动弹出，并支持逐条确认和一键全部确认。

本次发布必须保留旧 URL 和项目 ID，避免破坏浏览器本地数据、旧链接和搜索结果，同时把公开内容、源码快照、Windows 包、macOS 构建链路和 Apple 移动端入口更新到当前产品。

## 目标

- 从同一份 v2.0.0 源码快照构建并验证 macOS arm64/x64 应用，更新安全下载清单与分片。

- 推送到 `wthpein010-dev/ai-application-hub`，合入 `main`，等待 GitHub Pages 和远端验证完成后再报告发布完成。

## 平台边界

### Windows

Windows v2.0.0 是完整原生产品：连接本机 `codex app-server`，扫描本机会话日志，显示置顶悬浮栏，并把确认消息发送到对应真实任务。下载包必须包含可运行 EXE 和说明文件，发布前执行 Release 测试、正式 EXE 烟测、ZIP 结构、大小和 SHA-256 校验。

### macOS

macOS v2.0.0 继续作为完整桌面产品，使用 arm64 和 x64 两个包。GitHub Actions 在真实 macOS runner 上测试、打包、ad-hoc 签名、检查 `.app` 结构、版本键和最小启动流程；随后把验证通过的包切分并回写发布分支。

### iOS / iPadOS

iOS 端以 Safari 可安装 Web App 发布，而不是伪造 IPA。iOS 沙箱不允许网页创建跨应用置顶悬浮窗、启动本机 Codex CLI 或读取电脑上的 Codex 会话，因此移动端定位为产品演示与伴侣入口：可离线查看产品流程、操作模拟候选、体验逐条/批量确认，并引导用户把网页添加到主屏幕。页面必须明确说明真实线程扫描和发送仍由 Windows/macOS 桌面端完成。

不发布未签名 IPA、源码 ZIP 冒充 iOS 应用或无法安装的占位包。未来若具备 Apple Developer 签名和安全的桌面配对服务，再单独设计原生 iOS 远程伴侣。

## 方案比较

1. **Windows + macOS 原生，iOS 使用可安装 PWA（采用）**：能立即提供真实可安装的 Apple 移动端入口，不需要伪造签名，且可如实表达平台边界。
2. **直接构建未签名 IPA（否决）**：普通用户无法安装，违反下载包必须真实可用的发布约束。
3. **把用户的“iOS”解释成 macOS（否决）**：会忽略明确的 iPhone/iPad 诉求；本次保留 macOS，同时增加独立 iOS 入口。

## 交互演示

桌面模拟区域以屏幕顶部为主视觉。初始状态只显示 10px 绿色把手；鼠标或键盘聚焦后滑出空闲状态条，离开后延迟收回。点击“模拟待确认出现”后，悬浮栏自动展开两条候选并显示“确认继续”和“一键全部确认”。逐条确认会把该项切换为已发送并移除；列表清空后自动回到贴顶状态。点击“模拟扫描异常”会展开异常状态，但不显示可误触的确认动作。

交互必须支持鼠标、键盘和触摸；移动视口不能依赖 hover 才能访问内容。

## 数据与安全

- 公开演示和 iOS Web App 只使用明确标注的示例数据，不连接真实 Codex，不收集或上传聊天内容。
- Windows/macOS 原生应用继续只连接本机 Codex，不读取或保存登录凭据。
- iOS service worker 只缓存自身静态外壳；不得缓存下载分片、用户输入或任何私密数据。
- 下载清单固定文件名、总字节数、分片字节数和 SHA-256；校验失败不得触发保存。
