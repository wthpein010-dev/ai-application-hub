## 目标

把 Hub 从“入口都存在”提升为“每个公开项目的名称、文案、视频、子页、按钮、资源和跨平台声明都有证据”。审计不仅检查 HTTP 200，还检查资源是否属于正确项目、是否能真实使用、是否符合当前分类与页面规范。

## 真实性规则

1. `app-20260706-restore-games.js` 是唯一运行时清单；旧脚本不得继续作为可误用的第二份权威清单。
2. 小游戏、AI 版和工程体验只显示“演示 / 视频”，不把 Unity 工程、WebGL 导出或微信包标成系统下载。
3. 纯网页工具在 Windows 与 macOS 浏览器均可查看，卡片只显示“演示 / 视频”。
4. 只有具有真实可运行 Windows 与 macOS 成品和验证证据的桌面产品显示四按钮。当前可保留四按钮的原生产品为 `codex-quota-bar`、`codex-thread-workbench`、`clickflow`、`pureshrink`；浏览器扩展只有在同一扩展包确实跨平台时才允许两个系统入口指向同一文件。
5. 源码、说明页、错误项目压缩包、通用网页 ZIP、WebGL ZIP 和 Unity 工程不得使用“Wins下载 / Mac下载”。
6. 无法在某平台证明可运行时，保留跨平台网页体验并移除误导下载；不以占位包补齐按钮。

## 分类规则

- `status: game` 进入 `#games`。
- `status: engineering` 与 `status: ai` 进入 `#engineering`；`羊了个羊：对对碰` 继续遵循用户确认的 AI 版工程体验口径。
- 其余状态进入 `#apps`。
- `planner-daily-quiz` 必须把旧缓存中的历史 `game` 状态迁移为 `training`。
- `馕了个馕` 必须只在 `#games` 出现，公开名不得回退。

## 文案规则

- 名称与项目页标题使用同一公开名称。
- 卡片 `brief` 只说明用户得到什么，不复述标签；`problem` 说明使用场景；`aiUse` 说明 AI 的具体参与方式。
- 文案通俗、精简，不写无法由当前产品证明的能力。
- 保留用户已经在线固化的主页标题和副标题，不用默认文案覆盖自定义文本。

## 视频规则

- 24 张卡片均提供本地 H.264 MP4，时长不超过 4 分钟，使用统一延迟加载播放器。
- 视频页返回按钮必须回到卡片所属分区：`#apps`、`#games` 或 `#engineering`。
- 有字幕时，每个 cue 只允许一行、时间不重叠、不得超过视频时长；项目名称必须与当前卡片一致。
- 竖屏视频允许在共享播放器中使用竖屏舞台模式，不能用固定 16:9 大黑边当作唯一呈现。
- 视频内容需与当前项目功能相符；旧名称、占位画面和错误项目内容必须替换。

## 子页规则

- 所有本地演示页有统一左上角“返回主页”按钮，并返回正确分区。
- 视频页共享 `assets/hub-video-player.css` 与 `assets/hub-video-player.js`。
- 桌面 `1440x900` 与手机 `390x844` 无横向溢出、遮挡、空白首屏和控制台错误。
- 游戏可保留自身画布比例，但外壳、返回按钮、加载失败提示和页面标题必须统一。

## 清理规则

- 从公开仓库移除未进入清单且仍是方案/视频占位的目录与压缩包。
- 移除错误项目、污染内容或仅源码的公开下载包；保留真正发布资产和生成它们所需的源代码。
- 删除文件前由测试证明没有当前卡片、页面、脚本、文档或工作流引用。
