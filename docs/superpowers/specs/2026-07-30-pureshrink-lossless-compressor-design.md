# PureShrink 无损压缩工坊设计

## 产品目标

PureShrink 是一个优先保护原件、默认不上传文件的批量媒体压缩工具。它同时提供 GitHub Pages 在线版与 Windows、macOS 桌面版，面向需要集中处理图片、视频、GIF、音频和一般文件的普通用户。

首个公开版本必须做到：

- 网页端能直接添加、排队、压缩并下载多种资源。
- 桌面端复用同一套交互，并使用本机原生 FFmpeg 处理大文件。
- 默认使用“严格无损”：不改变可解码的画面与声音内容；只有结果更小时才提供新文件。
- 提供“高保真”作为明确标注的可选模式，换取更高压缩率。
- 每个文件显示原始大小、输出大小、节省率、处理状态、所用策略和失败原因。
- 不覆盖原件，不自动上传，不把源文件或文件名写入远程日志。
- 按 AI Application Hub 规范提供演示、视频、Wins下载和 Mac下载四个公开入口。

## 口径与边界

“严格无损”按媒体类型定义：

- PNG：重新编码后逐像素 RGBA 一致；若结果没有更小，保留原件。
- JPEG、WebP、AVIF、GIF：优先移除可安全移除的容器元数据或重封装压缩码流，不重新量化画面；无法证明更小时保留原件。
- MP4、MOV、MKV、WebM、MP3、M4A、WAV、FLAC：复制音视频码流并重建容器、移除非必要元数据；音视频码流不重新编码。
- PDF、ZIP、文档和其他文件：使用 ZIP Deflate 做字节级无损归档；若压缩包不更小，保留原件。

“高保真”不是无损模式。图片默认转为高质量 WebP，视频默认使用 H.264 CRF 18 和 AAC 192 kbps，GIF 使用调色板优化与帧率上限。界面必须持续显示这一差别，不得把高保真输出称为无损。

浏览器版以单个文件 2 GB 以下为目标，推荐视频不超过 500 MB；受浏览器内存限制时给出明确提示并推荐桌面版。首个版本不提供云存储、账户、跨设备同步、DRM 文件处理或对已加密文件的破解能力。

## 方案比较

### 方案 A：纯浏览器工具

使用 Canvas、CompressionStream 和 FFmpeg.wasm 完成全部处理。部署最简单、隐私边界清楚，但大视频速度慢、浏览器内存限制明显，也不能提供真正稳定的桌面大文件体验。

### 方案 B：Electron + 独立网页实现

桌面端用 Electron/FFmpeg，网页端另外开发一套页面。原生处理能力强，但两套界面和队列逻辑容易逐渐分叉，长期维护成本最高。

### 方案 C：共享界面 + 双执行引擎

网页和 Electron 复用同一套静态 HTML/CSS/JavaScript。网页端懒加载单线程 FFmpeg.wasm 与 fflate；桌面端通过受限 preload API 调用随包附带的 FFmpeg。队列、策略说明、结果统计和无损口径共用，只有文件选择、处理器和保存方式不同。

采用方案 C。它保留网页即开即用的优势，同时让桌面版能够处理大文件，并把长期需要维护的产品交互收敛到一处。

## 视觉与交互

视觉方向为“精密实验室”，而不是传统工具软件的灰色表格。页面使用深墨绿背景、酸橙色状态色和暖白色文字；背景以细网格、柔和光斑和压缩前后数据轨道构成。不得依赖装饰性插画。

首屏由三部分构成：

1. 左侧品牌与一句可验证承诺：“文件不离开设备，原件永不覆盖。”
2. 中央大型拖放区，支持点击选择、拖入、键盘聚焦和桌面端原生选择。
3. 右侧“严格无损 / 高保真”模式卡，列出当前策略的真实含义。

加入文件后进入工作台：

- 顶部汇总文件数、原始总大小、预计/实际输出大小和累计节省率。
- 中间为队列，每项显示类型图标、文件名、大小、状态、策略、进度和结果操作。
- 底部固定操作条提供“开始压缩”“暂停后续任务”“清空已完成”“下载全部”。
- 桌面版额外提供输出目录和“在文件夹中显示”。
- 空队列、运行中、成功、未变小、取消和失败都有独立文案，不能只靠颜色表达。

页面沿用 Hub 的固定“返回主页”按钮与公共背景框架。移动端以单列为主，底部操作条允许换行但不产生横向滚动。

## 架构

### 共享网页

`projects/pureshrink/` 保存可直接由 GitHub Pages 提供的产品：

- `index.html`：语义结构、可访问标签、隐私和模式说明。
- `styles.css`：品牌视觉、响应式布局和状态样式。
- `app.js`：队列控制、模式切换、事件绑定、统计和下载编排。
- `core/policy.mjs`：根据扩展名、MIME 和模式选择处理策略。
- `core/queue.mjs`：纯状态机，管理等待、运行、完成、保留原件、失败和取消。
- `core/metrics.mjs`：大小格式化、节省率和汇总计算。
- `engines/browser-engine.mjs`：懒加载 FFmpeg.wasm/fflate，负责浏览器内处理。
- `engines/desktop-engine.mjs`：调用 `window.pureShrinkDesktop`，不接触 Node 全局。
- `vendor/`：提交经过版本锁定的轻量浏览器装载代码；FFmpeg core WASM 由固定版本 CDN 懒加载。

在线版的所有源文件只保存在当前浏览器内存或用户主动下载的 Blob 中。页面不包含上传请求。

### 桌面应用

`build/pureshrink-desktop/` 保存 Electron 外壳：

- `main.cjs`：创建隔离窗口、文件选择、输出目录、FFmpeg 子进程和安全 IPC。
- `preload.cjs`：只暴露文件选择、压缩、取消、显示结果和版本信息。
- `native/policy.cjs`：把共享策略映射为经过白名单限制的 FFmpeg 参数。
- `native/runner.cjs`：用参数数组启动 FFmpeg，解析进度，永不执行 shell 字符串。
- `package.json`：锁定 Electron、electron-builder 和 ffmpeg-static。
- `scripts/verify-package.mjs`：检查产物入口、FFmpeg、版本和文件结构。

桌面输出默认写入用户选择的目录；未选择时使用“文档/PureShrink Output”。输出文件名增加 `-pureshrink`，冲突时追加递增序号。任何失败都不得删除或修改源文件。

### 发布与 Hub 接入

- `app-20260706-restore-games.js` 在应用集合末尾注册 PureShrink。
- `projects/pureshrink/video/` 保存统一视频页、H.264 教程、单行中文字幕、海报和脚本。
- `.github/workflows/build-pureshrink-release.yml` 在 Windows 与 macOS runner 上分别构建、运行最小启动/包结构验证，再创建 `pureshrink-v1.0.0` Release。
- `projects/pureshrink/release-manifest.json` 记录最终资产名、字节数、SHA-256、平台入口和 Release URL。

## 数据流

1. 用户拖入或选择文件。
2. 前端根据名称、MIME、大小与当前模式生成不可变任务描述。
3. 队列逐个执行任务，避免多个 FFmpeg 实例同时耗尽内存。
4. 引擎返回输出句柄、输出大小、策略说明和验证结论。
5. 严格无损模式下，如果输出不小于原件，任务进入“保留原件”而不是伪造节省结果。
6. 网页端为输出创建临时 Object URL；桌面端返回本地输出路径。
7. 用户主动下载、显示或清除结果后释放临时资源。

取消只终止当前任务并把后续任务留在等待状态。切换模式只影响尚未开始的任务，已完成结果不被静默替换。

## 错误处理

- 不支持的格式：转入字节级 ZIP 无损归档，并显示回退原因。
- FFmpeg core 加载失败：保留队列和原件，提供重试；不自动上传到服务器。
- 浏览器内存不足或文件过大：停止当前任务，推荐桌面版并保留其他任务。
- 输出更大：删除临时输出并标记“原件已是更优结果”。
- 桌面输出目录不可写：不回退到覆盖源目录，要求重新选择目录。
- FFmpeg 返回非零：保留 stderr 的安全摘要，不显示绝对源路径。
- 页面关闭或刷新：明确提示尚未下载的内存结果会丢失；不承诺浏览器内持久化。

## 安全与隐私

- Electron 使用 `contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`。
- IPC 通道和参数固定白名单；FFmpeg 使用 `spawn(binary, args)`，不经过 shell。
- 导航限制为本地产品页和系统浏览器中的 HTTPS 链接。
- 不加载远程执行脚本到桌面版；桌面版的处理与界面资源全部随包提供。
- 网页版仅从固定 HTTPS 版本地址加载 FFmpeg core；装载失败时拒绝降级到未知版本。
- 不收集文件名、媒体内容、路径、哈希、设备标识或压缩历史。

## 测试与验收

自动测试必须覆盖：

- 策略映射：图片、视频、GIF、音频、一般文件与两种模式。
- 队列状态机：顺序执行、取消、失败继续、清理和汇总。
- 大小与节省率计算：0 字节、输出变大和混合状态。
- 页面契约：拖放、文件选择、模式说明、隐私承诺、四类状态和无空链接。
- Electron 安全：隔离配置、IPC 白名单、无 shell、输出不覆盖原件。
- 打包契约：Windows EXE、macOS arm64/x64 App、FFmpeg 二进制和 README。
- Hub 契约：应用集合末尾、四入口顺序、Release 链接和本地地址泄漏扫描。
- 视频契约：H.264、时长不超过 240 秒、字幕单行且时间不重叠。

本地与发布后浏览器验收覆盖桌面 `1440×900` 和移动 `390×844`：添加测试图片、GIF 和短视频，完成严格无损处理，下载结果，确认无横向溢出、无控制台错误、状态可读。Windows runner 必须实际启动应用并完成一项最小压缩；macOS arm64/x64 构建必须在对应 runner 完成启动或等价命令行处理证据。最终再验证 Hub 卡片、演示页、视频播放、两个下载 URL、资产大小与哈希、GitHub Pages workflow 和远端提交 SHA。

## 版本一完成定义

只有以下条件全部满足才可宣布完成：

1. 在线版在公网完成至少一张图片、一个 GIF 和一个短视频的真实处理。
2. 严格无损输出具有对应的像素、码流或字节级验证证据。
3. Windows 与 macOS Release 资产来自各自平台 CI，能够解压且包含正确入口。
4. 教程视频可在公网浏览器点击播放，字幕任一时刻只显示一行。
5. PureShrink 位于 Hub 应用集合最后，四个按钮顺序与目标正确。
6. 全部自动测试、Pages 部署和公网逐链接验收通过。
