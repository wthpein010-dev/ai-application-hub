# ClickFlow 卡片标签与名称优化设计

日期：2026-07-30  
状态：已确认命名方案，待实施

## 背景

AI Application Hub 中的 ClickFlow 卡片当前标题为“ClickFlow 鼠标自动化工作台”，蓝色标签为“Windows · macOS”。标题偏长，蓝色标签表达的是平台而不是工具类型，与卡片的分类语义不一致。

## 已确认设计

- 卡片公开名称改为“ClickFlow 鼠标自动化”。
- 蓝色标签改为“辅助工具”。
- ClickFlow 的目录状态改为 `assistant`，与 Hub 已有的“辅助工具”类型一致。
- 卡片右上角分类“桌面自动化工具”保持不变，用于补充具体用途。
- “演示 / 视频 / Wins下载 / Mac下载”四个入口、顺序和 URL 全部保持不变。
- ClickFlow 演示页、视频页、桌面应用窗口、安装包名和 GitHub Release 名称保持不变。本次仅优化 Hub 卡片公开信息。

## 旧浏览器缓存迁移

Hub 会从 `localStorage` 恢复用户曾经浏览或编辑过的卡片数据。为避免老用户刷新后仍看到旧信息：

- 仅当 ClickFlow 名称仍等于旧默认值“ClickFlow 鼠标自动化工作台”时，迁移为新名称。
- 仅当 ClickFlow 标签仍等于旧默认值“Windows · macOS”时，迁移为“辅助工具”。
- 旧默认状态 `desktop` 迁移为 `assistant`。
- 用户已经修改过的其他名称、简介、标签和分类不覆盖。

## 测试与发布

- 目录测试验证新名称、`assistant` 状态和“辅助工具”标签。
- 缓存迁移测试验证旧默认值会更新，并验证自定义名称不会被覆盖。
- 浏览器验收验证 ClickFlow 仍是应用集合末尾卡片，四个入口保持原顺序。
- 更新主页运行时缓存键，推送到 `main`，等待 GitHub Pages 成功后在公网检查桌面和手机布局、卡片文本、下载链接与浏览器错误。

## 完成标准

- 公网页面显示“ClickFlow 鼠标自动化”和“辅助工具”。
- 四个入口完整可用，Windows/macOS 下载链接未变化。
- 新访客与保存过旧默认数据的访客都能看到新名称和标签。
- 完整 Hub 回归、ClickFlow 浏览器验收和 GitHub Pages 部署均成功。
