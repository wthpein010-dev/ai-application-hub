# Paws 试玩实机一致性与 3D 深度稳定设计

**日期：** 2026-07-22
**状态：** 已确认（用户要求直接开发，并以 Unity 编辑器与实机规则为权威）

## 目标

在既有“AI 同层零面积重叠、总数为偶数、逐层与全局图案计数为偶数、确定性完整求解”门禁之上，补齐网页试玩与 Unity 的第一回合随机出盘差异，并保证历史关卡即使保留旧式同层重叠，3D 预览也不再因共面深度竞争而闪烁。

## 已确认根因

AI 生成器当前已经在落位阶段禁止同层正面积相交，旧浏览器 AI 文档也会在打开时迁移；固定标准种子的生成、校验和完整试玩均已证明重叠为 0。因此新的 AI 数据不能通过抬高砖块来掩盖坏布局。

仍存在两条独立兼容路径：

1. 网页 `random-assigner.mjs` 对 `type=0/-1` 只做全盘成对打散；Unity `LevelSceneTileTypeAssigner` 对第一回合会合并两类随机标记，按层单色、层间尽量使用不同图案出盘。
2. 22 个授权内置关中仍有历史同层部分重叠。它们必须继续原样读取和导出，但完全相同的 3D 高度会导致共面 z-fighting。

## 第一回合识别与分配

- 文件名含 `_rN_` 时严格使用 N；`_r1_` 是第一回合，其他回合不是。
- 文件名没有回合标记时，以 Unity 编辑元数据 `gameplay.gameLevelOrder === 1` 作为网页可获得的回退信号。
- 第一回合合并 `type=0` 与 `type=-1`，按层升序分组；同一层的所有随机标记分配为同一具体图案。
- 图案优先来自 `1..blockTypeCount`；图案数少于随机层数时扩展到最多 32，确保常规第一回合层间互异。
- 每层随机砖块数必须为偶数；否则明确拒绝试玩，不能生成一个表面可点但无法清空的出盘。
- 第二回合及普通试玩保持现有规则：两类随机标记分别使用自己的范围生成全局偶数对。
- 固定图案不被重写；相同种子重开结果一致，不同种子仍可改变层与图案的映射。

## 历史重叠的 3D 兼容渲染

- JSON、编辑坐标、覆盖关系、难度与求解数据保持不变。
- 只对棋盘上同层正面积相交的砖块建立冲突图，按稳定顺序贪心着色。
- 颜色 0 不偏移，颜色 N 的 `worldY` 增加 `N × 0.001` 世界单位；边缘相接、跨层相交、托盘砖块不偏移。
- AI 严格门禁和历史重叠警告继续保留。视觉偏置只是旧数据兼容，不得用于放宽 AI 生成规则。

## 试玩引擎回归范围

直接单元测试覆盖：第一回合分层单色、第二回合全局配对、选择与取消、翻面错配回翻、翻面匹配、双暂存槽、特殊牌自动消除、死局、相同/不同种子重开，以及完整两两消除胜利。2D/3D 继续消费同一份 `playSnapshot`，不引入视图专用游戏状态。

## 验收

- 新回归测试必须先在旧实现上失败，再由最小实现转绿。
- 全部 Paws Node 测试、模块语法检查和 `git diff --check` 通过。
- 浏览器对真实 `_r1_` 关验证逐层单色、层间互异和完整清空；对 AI 标准关验证 200 张、15 层、同层重叠 0、100 步获胜。
- 3D 验证历史重叠砖块具有不同显示高度且源 JSON 坐标/层级未改变。
- 发布后等待 GitHub Pages 对应提交上线，再重复 HTTP、浏览器、3D 与完整试玩验收。
