# 砖块小人参考图鉴改版设计

## 目标

把公开的“砖块小人与随身小物图鉴”改造成横向三栏检查工作台：左侧展示一次获得角色皮肤的结算效果，中间展示游戏式图鉴列表，右侧同屏展示较小的角色详情，以便同时检查角色形象、名称与文案实际换行。

## 参考与范围

- 截图 1 定义“获得角色 → 图鉴列表 → 角色详情”的三段同时可见关系，以及黑色舞台、白色游戏面板、红色飘带、聚光灯和结算感。
- 截图 2 定义图鉴的标签切换、关闭、收集进度、当前分类搜索、批量收藏、状态卡片、收藏筛选与分页行为。
- `blockskin.xlsx` 的 `Sheet1` 是角色皮肤目录。只使用 `show = 1` 的行，并按 `stringsequence` 升序显示。
- 每个可见皮肤的 `blockname`、`UnownedDesc`、`UnlockDesc`、`GalleryDesc` 都作为公开数据中的可审计 key；简体中文文字只从 `language.xlsx` 的 `language0`、`zh` 列按 `id` key 取得。

## 布局与交互

桌面端采用三栏横排：结算预览约 290px、图鉴约 560px、详情约 410px；三个面板顶部对齐。角色图片在卡片和详情中都以现有显示尺寸的 `1 / 1.5` 作为最大视觉比例，始终通过限制容器和 `object-fit: contain` 保持在边框内。窄屏降为纵向阅读顺序，不产生横向滚动。

结算面板使用当前选中角色，显示“恭喜你 / 获得新皮肤”、角色名称、角色形象、从 `UnlockDesc` 得到的短提示、勾选态“立即装扮新的砖块皮肤”、返回主页和分享动作。它是纯展示预览，不伪造真实奖励或写入游戏数据。

中间图鉴保留“砖块小人 / 随身小物”分类、当前分类搜索、收集数、批量收藏、收藏筛选和分页；增加游戏式关闭动作。默认角色仍全部解锁，卡片显示“已获得”；当前被设为装扮预览的角色显示“装扮中”，首次被选中的角色可显示“新获得”。不虚构未解锁进度，但组件样式支持后续接入该状态。

右侧角色详情缩小并与列表同屏：名称飘带、居中角色、前后切换、获取说明、收藏/装扮/分享、页码和真实文案诊断均保留。详情和结算同时读取当前选中角色，不再以遮罩或弹板覆盖列表。

## 数据与同步

新增一个零依赖的 XLSX 读取层，仅读取 ZIP 内的 shared strings 与第一个工作表 XML，拒绝缺失工作表、重复皮肤 ID、缺少语言 key、非连续图鉴顺序和不安全输入。同步脚本显式接收 `PAWS_HOME_DATA_ROOT`，生成并写入公开 `data/characters.json`，不写入或公开机器本地路径。

公开数据每条都保留 `sourceKeys`（四个语言 key）、`unownedDesc`、`unlockDesc` 和 `galleryDesc`。层贴图与完整预览图片的现有同步逻辑保持不变；角色名称和三段文案以表格数据为准。

## 验收

- 数据测试验证 45 条可见皮肤、表格排序、全部语言 key 和公开字段。
- 页面测试验证三栏、结算面板、关闭动作、状态卡片和小型防溢出类。
- 浏览器 smoke 在桌面、窄桌面与手机验证选中角色后结算/列表/详情同时更新、图片边界不溢出、搜索/收藏/分页有效、无控制台错误和横向滚动。
- 发布前运行相关 Node、浏览器、Hub 审计测试；合并后验证 GitHub Pages 与公开页面。
