# Paws AI 关卡同层零重叠设计

**日期：** 2026-07-22
**状态：** 已确认（用户明确要求同层砖块不发生任何面积重叠，并要求总数与图案可两两消除）

## 目标

修复 AI 关卡在 3D 视图中的砖块闪烁。AI 生成结果必须同时满足：固定 7×8 棋盘、同层砖块面积零重叠、砖块总数为偶数、每种实际图案可两两消除、确定性求解器能够完整清空。跨层覆盖继续用于形成遮挡、路线与难度。

## 根因与参考规则

网页生成器当前只用 `layer|x|y` 锚点去重。两个 8×8 微格砖块只要锚点不同，即使足迹部分相交也可落在同一层。固定种子实测的九组“难度 × 布局”结果均含同层重叠，单关约 24–98 组；同层共面的 3D 顶面因此发生 z-fighting。

Unity 工程提供以下权威规则：

- 棋盘默认 7×8，每块砖占 8×8 微格。
- `SheepBoardLayout.TryValidateTilePairing` 要求总数、两类随机标记和每种固定图案数量为偶数。
- `LevelSceneTileTypeAssigner.BuildPairedTypePool` 每次加入两张同图案砖；`TryAssignLayerLocalPairs` 可保证每层各图案数量为偶数。
- `LevelSceneRandomAssignValidator.TryValidatePlayableLayout` 不只检查偶数，还检查开局对子和递归可清空。
- `LevelSceneLevelLoader.ParseTiles` 以 `repairOverlapLayers:false` 加载，不会自动修复同层坏数据。

历史 30 个内置关中有 12 个含旧式同层部分重叠，因此新的严格门禁只对 AI 生成关生效，不能阻止历史关卡打开和试玩。

## 方案选择

采用“生成时硬约束 + AI 专用校验门禁 + 求解门禁”。

- 不采用 3D 高度偏移：它只掩盖坏布局，2D/求解数据仍不正确。
- 不采用生成后重新分层：它会改变用户要求的层数、遮挡结构和难度评分。
- 不把同层重叠设为所有关卡的全局错误：这会破坏 12 个历史内置关的兼容性。

## 生成规则

砖块足迹为半开矩形 `[x,x+8) × [y,y+8)`。同层两砖只有在以下条件同时满足时才算面积重叠：

```text
abs(left.x - right.x) < 8
and abs(left.y - right.y) < 8
```

差值等于 8 只是边缘相接，允许放置。

生成器从塔顶向下逐层选位。每层使用 `[0,0]`、`[2,2]`、`[4,4]`、`[6,6]` 四相位循环的 8 微格左右对称候选池；候选对子内部以及候选与本层已选砖之间都必须零面积相交。只要仍有合法候选可被直接上层覆盖，就优先选择被覆盖候选；真实支撑容量耗尽后才选择开放候选，避免困难模式“1 对塔顶必须直接覆盖 5 对子砖”这类物理上不可能的装箱要求。下一层可支撑候选数、额外跨层阻挡数和父砖复用均参与排序。相同锚点最多跨层复用两次，与既有“精确堆叠深度不超过 2”门禁一致。

## 配对与可玩规则

- 用户输入奇数总数时沿用现有规则，自动向上补成偶数。
- 生成器仍以“对子”为最小单位创建砖块，同一对子使用相同 `type`。
- 每个对子完整放在同一层，所以每层每种图案计数与全局每种图案计数均为偶数。
- 偶数计数只证明牌面可配对，不证明顺序可玩；生成候选仍必须通过 `solveLevel`，成功步数必须等于砖块总数除以 2。

## 防御性校验

`validateLevel` 增加同层面积相交检测。默认仅当文档含 `designerNote.aiGeneration` 时把该问题记为 `same-layer-overlap` 错误；生成器会显式启用严格选项作为发布门禁。历史内置关保持原有读取行为。

AI 候选必须依次通过：

1. 基础字段、边界、总数和图案偶数校验；
2. 同层零重叠校验；
3. 既有跨层遮挡预算、精确堆叠深度与开局对子门禁；
4. 确定性完整求解；
5. 五维难度评分。

## 测试与验收

- 单元测试先证明同层部分相交会被 AI 门禁拒绝，边缘相接不会被误判。
- 固定种子回归覆盖简单/标准/困难与均衡/层层推进/开阔九种组合，并补充多种子统计；每组断言同层重叠对数为 0。
- 断言奇数请求自动补偶数、总数为偶数、每层每种图案为偶数、全局每种图案为偶数、求解步数为 `tileCount / 2`。
- 运行全部 Node 测试、模块语法检查与 `git diff --check`。
- 在桌面浏览器生成标准 200 张/15 层关卡，切换 3D 并完整试玩；确认无控制台、页面、请求或 HTTP 错误。
- 发布后等待 GitHub Pages 对应提交上线，再重复线上 HTTP 与浏览器验收。
