# 小游戏立项工具网页演示与视频设计

## 目标

把“小游戏立项模拟器”改名为“小游戏立项工具”，从小游戏体验集合迁入应用项目集合，并提供完整可操作的网页演示、Windows 下载和不超过 3 分钟的中文配音介绍视频。

## 首页信息架构

- 应用名称：`小游戏立项工具`
- 所属区域：应用项目集合
- 类型：`assistant`，页面徽标显示“辅助工具”
- 分类：`游戏立项与需求工具`
- 标签：`微信小游戏`、`Unity`、`需求文档`、`Codex`
- 入口顺序：`演示`、`Wins下载`、`视频`
- 小游戏集合不再包含该项目；应用统计增加 1，小游戏统计减少 1。

## 网页演示

演示页使用原生 HTML、CSS 和 JavaScript，托管在 GitHub Pages，不依赖服务器。页面以桌面版的主要工作流为准，提供：

1. 快速开始：项目名称、游戏类型、核心循环、画面风格和目标平台。
2. 高级问卷：Unity、UGUI、750×1624 设计画布、分辨率适配、微信能力、性能预算、资源策略、验收标准和版本回退。
3. 浏览器本地草稿：字段变化后写入 `localStorage`，刷新后恢复。
4. 完整度检查：列出关键缺失项，点击问题可定位到对应字段。
5. Markdown 预览：将通用 Unity 微信小游戏开发记忆与用户答案合并为一个可交给 Codex 的文档。
6. Markdown 下载：浏览器下载 `.md` 文件；网页端不模拟 Windows 的“打开文件夹”能力。
7. 通用开发记忆：通过弹窗或抽屉查看默认记忆内容。

页面采用高对比度深色界面，桌面端使用侧栏与内容区布局，窄屏切换为单列；所有输入、下拉框、按钮和弹窗满足清晰可读与键盘操作要求。

## 数据与生成规则

- 问卷定义集中在独立 JavaScript 数据结构中，包含字段键、标题、说明、选项、是否关键和所属分组。
- 草稿保存为版本化 JSON；遇到损坏或未知版本时回退到默认值，不阻断页面。
- 完整度检查只把项目名称、游戏类型、核心循环、画面风格和目标平台作为首轮关键项；高级问题允许后续补充。
- Markdown 文件名使用清理后的项目名；项目名为空时使用 `小游戏立项需求.md`。
- 生成文档包含项目摘要、核心玩法、技术基线、界面与适配、微信平台、资源策略、性能与验收、版本管理、缺失项清单和通用开发记忆。

## 视频设计

视频目标时长为 2 分 40 秒至 3 分钟，分辨率 1920×1080，格式 MP4（H.264 视频、AAC 音频）。使用本机 `Microsoft Huihui Desktop` 中文女声生成旁白，并叠加同步中文字幕。

章节：

- 0:00–0:20：工具用途与适用场景。
- 0:20–1:05：回答五个核心问题。
- 1:05–1:45：展开高级问卷和风格选择。
- 1:45–2:15：检查缺失项并补充。
- 2:15–2:45：预览和下载 Markdown，说明拖入 Codex 的使用方式。
- 2:45–结束：Windows 单文件版下载提示。

录制使用固定演示数据和可重复的操作脚本。视频页先显示介绍与加载按钮，用户点击后才加载 MP4；同时提供直接打开视频文件和返回演示页的入口。

## 文件边界

- `projects/minigame-project-tool/index.html`：演示页结构。
- `projects/minigame-project-tool/styles.css`：演示页响应式视觉样式。
- `projects/minigame-project-tool/app.js`：问卷、持久化、完整度检查、Markdown 生成与下载。
- `projects/minigame-project-tool/video/index.html`：视频播放页。
- `projects/minigame-project-tool/video/minigame-project-tool-intro.mp4`：最终视频。
- `projects/minigame-project-tool/video/minigame-project-tool-intro.vtt`：字幕文件。
- `scripts/record-minigame-tool-demo.*`：可重复录制脚本与旁白时间轴。
- `tests/minigame-project-simulator.test.mjs`：首页元数据、演示页和视频资源回归测试。

## 错误处理

- localStorage 不可用时继续在内存中工作，并显示轻量提示。
- Markdown 下载失败时保留预览内容，提示用户复制。
- 视频未加载或浏览器不支持播放时提供 MP4 直接链接。
- 首页入口必须使用相对路径，确保本地服务器与 GitHub Pages 均可访问。

## 验收标准

1. 首页应用项目集合显示“小游戏立项工具”，小游戏集合不再显示它。
2. 卡片包含“演示”“Wins下载”“视频”三个有效入口。
3. 网页演示可填写、保存、恢复、检查缺失项、预览并下载 Markdown。
4. 桌面与 390px 窄屏均无横向溢出，文字和表单具有足够对比度。
5. MP4 时长不超过 180 秒，包含中文旁白和字幕，视频页可直接播放。
6. 首页、演示页、视频页和 ZIP 在部署后均返回 HTTP 200。
7. 现有测试与新增测试全部通过；ZIP 内部 EXE 哈希保持不变。

## 回退策略

所有变更在独立 Git 分支完成，并按规格、网页功能、视频资源与发布入口分阶段提交。出现问题时可单独回退首页迁移、演示页或视频提交，不影响现有小游戏和其他应用。
