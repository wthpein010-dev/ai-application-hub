# 灯塔救援队：画面呈现后再交付直播回执

状态：沿用用户已确认的《灯塔救援队》完整开发与直接发布授权。公开版仍为本地模拟，正式 SDK 尚未获授权。

## 目的

抖音履约 ACK 表示互动已在玩法内处理和呈现。当前控制器在 `Update` 内更新 UI 后立即调用 `ILiveMessageSource.HandleReceipt`，此时 Unity 尚未完成这一帧渲染。改为完成画面帧后交付回执，保证适配器不早于实际画面接到可履约消息。

## 行为

- 主线程 `Drain` 保持规则裁决、持久日志追加和 UI 反馈顺序；所有已处理消息的 `LiveInboxReceipt` 进入最多 256 条的待呈现队列，不在同一次 `Update` 内交给消息源。
- Windows 播放器用单个 `WaitForEndOfFrame` 协程在画面完成后清空队列；无需每帧创建协程或对象。一次画面可合并展示同帧多条互动的最终状态，回执仍逐条保留原始 `MsgId`/`MsgType` 和处理结果。
- 普通断线时，断线前已入队的消息仍可完成呈现，并把结果交给适配器，由适配器决定网络回执重试；故障、输入过载、重置或换局时抑制尚未呈现的回执。队列积压达到上限时按回执故障停机，不继续无界累积。
- `HandleReceipt` 抛异常时沿用既有“回执故障”停机与持久状态回退。同一帧内已处理的多条互动已逐条持久化，即使首条回执失败也保留这帧的持久状态；故障前已交付的回执不撤回，未交付的回执不继续发送。
- 此处只约束向未来 SDK 适配器交付的时机；官方 `ReportAck`、重试语义与真实房间表现仍需授权 SDK 实测。WebGL 仍为模拟版。

## 验证

- EditMode 注入帧边界：`Update` 后没有回执；模拟画面完成后，已写盘的消息逐条交付。断线重连、重置和故障时验证保留或抑制策略；256 条上限验证停机与无界内存保护。
- 完整 Unity EditMode 与 Windows/WebGL 构建；Windows 全新解压短/长路线，桌面与 390px WebGL 整局及恢复；发布后核对精确 SHA 的 Pages/CI、视频与下载包哈希。
