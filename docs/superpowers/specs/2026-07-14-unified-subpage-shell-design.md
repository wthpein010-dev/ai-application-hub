# 统一子页面视觉外壳设计

## 目标

统一主页中所有应用、小游戏和介绍视频所进入子页面的返回入口与背景氛围，同时保留每个项目原有的内容、排版、交互和画面比例。

首轮只改造“小游戏立项工具”网页作为本地样板。用户确认样板后，再把相同规则推广到其余子页面并发布到 GitHub Pages。

## 样板范围

- 样板页面：`projects/minigame-project-tool/index.html`
- 共用样式：新增 `assets/subpage-shell.css`
- 共用背景：复用主页已有的 `assets/hero-ai-companion.png`
- 样板阶段不修改主页、不修改其他项目页、不推送线上页面。

## 视觉与交互

- 左上角固定显示唯一的 `返回主页` 按钮，使用左箭头图标与中文文本。
- 按钮最小高度 42px，箭头和文字垂直居中；桌面端距边缘 18px，移动端兼容安全区域。
- 按钮使用半透明深色底、清晰边框和轻阴影，在浅色及深色背景上均保持可读。
- 点击按钮使用相对路径返回仓库根目录 `index.html`，不附带 `#apps`、`#games` 等锚点。
- 页面背景复用主页的 AI 伙伴图，并通过低透明度和深色遮罩控制存在感，避免干扰表单、标题和正文。
- 样板页原有顶部品牌、功能视频、Windows 下载入口继续保留；原顶部右侧“返回主页”链接移除，避免同一页面出现两个返回入口。

## 推广规则

- 普通应用页：加载共用样式和背景，保留项目自己的内容容器。
- 视频页：使用同一返回按钮与背景，播放器区域不加滤镜、不改变比例。
- Unity/Canvas 小游戏页：使用同一返回按钮；背景只作用于画布之外，不覆盖或缩放游戏画面。
- 所有路径保持相对路径，兼容 GitHub Pages、本地文件夹拷贝、Windows 和 macOS。

## 失败与兼容处理

- 背景图片加载失败时自动回退为纯深色背景，文字和控件仍可正常使用。
- 不依赖外部字体、图标 CDN 或运行时脚本，避免离线打开和跨电脑拷贝时失效。
- 返回按钮使用原生链接，即使 JavaScript 关闭也能返回主页。
- 对已有固定导航或全屏画布页面使用更高层级和安全间距，避免遮挡核心控件。

## 验证

- 自动检查样板页只有一个统一返回按钮，目标为正确的根主页相对路径。
- 在桌面和移动视口截图，检查按钮、背景、正文和现有导航没有遮挡或溢出。
- 点击返回按钮，确认到达本地主页。
- 样板确认后，批量推广阶段再验证全部网页入口、介绍视频页和 Unity/Canvas 页。
