# Loop BGM Lab External Candidate Provenance and License Gate Design

## Context

Loop BGM Lab schema v2 assumes that every analyzed candidate belongs to a recorded Suno Create run. External music can therefore be analyzed only by attaching it to a Suno run, which creates false provenance and can mark a Suno batch as downloaded. License rows are not linked to candidates, ShareAlike is reduced to ordinary CC BY, and public preview files are indistinguishable from production originals.

This slice makes external and locally created music first-class research candidates while keeping production use conservatively blocked whenever identity or license evidence is incomplete. It also adds a portable JSON license-package format so a dated external-source manifest can move between computers without moving audio bytes, local paths, personal file names, credentials, or signed download URLs.

## Goals

- Distinguish `suno`, `external`, `local-original`, and migrated `legacy-unknown` candidate provenance.
- Let external and local-original audio be analyzed without creating or mutating a Suno run.
- Bind every recorded license to the exact candidate SHA-256; missing or mismatched evidence must remain visibly blocked.
- Preserve ShareAlike, NonCommercial, NoDerivatives, preview-only, evidence-date, license-URL, scope, rights-chain, and modification facts.
- Keep “research best candidate” distinct from “production release ready.”
- Import and export a strict `loop-bgm-license-package` v1 JSON document atomically, with conflict detection and an adapter for the existing external manifest schema v3.
- Migrate schema v1 and v2 projects to project schema v3 without inferring that an old candidate was actually generated by Suno.
- Keep the Markdown handoff envelope at version 1 and continue delegating restored state to the canonical project validator.

## Non-goals

- This feature does not download music, parse ZIP archives, embed audio, or fetch source pages.
- It does not decide that a Creative Commons declaration proves uploader ownership or complete commercial clearance.
- It does not make ShareAlike a simple commercial/noncommercial boolean; project-level compatibility still needs human review.
- It does not upload reference audio to Suno, automate authentication, bypass browser safety checks, call hidden endpoints, or add a paid API transport.
- It does not silently reclassify migrated candidates from URL shape, run history, file name, or display name.
- It does not treat a public HQ preview as the original file or carry a preview hash forward after the original replaces it.

## Project schema v3

Every candidate has a strict discriminated source:

```js
candidateSource:
  { kind: "suno", runId, outputIndex }
| { kind: "external", licenseId, fileSha256 }
| { kind: "local-original", licenseId, fileSha256 }
| { kind: "legacy-unknown", legacyRunId? }
```

For external and local-original candidates, `licenseId` must reference an existing license, and `candidateSource.fileSha256`, the candidate's existing `hash`, and the license's `fileSha256` must all be exactly equal. The repeated source-level hash is a validated assertion of which bytes that provenance statement covers; a mismatch invalidates the project rather than being normalized away. The browser may analyze a file in memory to discover its hash, but it does not persist the candidate when no unique matching license exists.

For `suno`, `runId` must reference an existing run and `outputIndex` must reference an existing output. The candidate's experiment must match the same run and output. For `external` and `local-original`, the experiment's `runId`, `outputIndex`, `generatedUrl`, and `generationConditions` are all null. Reviewing such an experiment never changes a Suno batch's current run, status, candidate, URL, or review fields.

Schema v2 candidates migrate to `legacy-unknown`. A unique historical experiment run may be retained only as `legacyRunId`; it is context, not proof of Suno origin. The migration chain is `v1 -> v2 -> v3`. Future versions remain rejected. The local-storage key stays unchanged so the existing value is migrated in place rather than orphaned.

## License evidence

The v3 license record retains the current stable ID, public source label, source page, author, downloaded/evidence date, exact file SHA-256, and optional attribution text. It adds:

```js
{
  licenseIdentifier,
  licenseUrl,
  evidenceUrl,
  evidenceCheckedAt,
  deliveryStatus: "original" | "preview-only" | "unknown",
  scopeNote,
  rightsChainStatus: "user-declared-original" | "source-declaration-only" | "independently-verified" | "unknown",
  evidenceSha256?,
  modificationNote?
}
```

`licenseIdentifier` is the machine-oriented value used for classification; the current human `license` text remains display evidence and backward-compatible input. URL fields accept HTTPS only and use the existing credential and secret-query rejection. Evidence hashes summarize separately retained evidence and never embed a page, screenshot, audio file, file name, or local path.

Derived license flags include `by`, `nc`, `sa`, `nd`, `cc0`, `previewOnly`, and `unknown`. At minimum these release blockers are supported:

- `license-hash-mismatch`
- `unknown-license`
- `missing-evidence`
- `preview-only`
- `noncommercial`
- `share-alike-review-required`
- `no-derivatives-review-required`
- `missing-attribution`
- `rights-chain-review-required`

The blocker list is derived and revalidated on import; supplied stale derived values are rejected. CC BY-SA and CC BY-NC-SA must never be reduced to ordinary CC BY. A preview can be analyzed, played, compared, and selected as the research favorite, but it cannot be labeled production-ready.

## License package v1

The independent JSON envelope is not the project schema and is not the external source manifest schema:

```js
{
  format: "loop-bgm-license-package",
  version: 1,
  createdAt: "YYYY-MM-DD",
  entries: [/* normalized license evidence */]
}
```

The parser enforces a bounded UTF-8 document size, a bounded entry count, exact keys, unique portable IDs, unique file hashes, HTTPS-only public URLs, normalized dates and hashes, and the same portable-safety boundary as project import. It rejects dangerous keys, credentials, secret-like URL parameters, local paths, audio bytes, waveform arrays, browser sessions, file names, direct download URLs, and signed download parameters.

An import is fully planned before it is committed:

- Same SHA-256 and the same normalized evidence is idempotently skipped.
- Same SHA-256 with conflicting license or provenance facts blocks the entire package.
- Duplicate/conflicting entries inside the package block the entire package.
- No partial license rows or candidate links are committed on failure.
- Successful import adds only normalized license rows; a later external/local candidate import resolves exactly one row by SHA-256.
- Existing candidates and `legacy-unknown` records are never reclassified or linked automatically.

The export contains normalized public evidence and a blocker summary only. It contains no audio, package-relative path, original file name, local path, direct download/final URL, HTTP ETag or Last-Modified header, preview CDN URL, `originalFile` object, cookie, token, API key, recovery key, or session data.

The external manifest schema-v3 adapter accepts only that exact dated format and maps each work/file record to public evidence. It discards the file `path` and every transport or local identity field. `deliveryStatus` values containing audition/preview map to `preview-only`; original attachments map to `original`; unrecognized values map to `unknown` and remain blocked.

## Browser flow

The candidate-import area starts with a source selector:

- **Suno result**: requires a selected recorded run and output. Existing batch synchronization behavior remains.
- **External music**: does not require a Suno run. After hashing, exactly one matching license is required; zero or multiple matches fail that file without project mutation and explain how to add or correct evidence.
- **Local original**: follows the same non-Suno path and requires exactly one matching user-declared-original license record.
- **Legacy, source unconfirmed**: displayed only for migrated data. The user may deliberately reclassify it through a validated action; the tool never guesses.

Every candidate card shows a source badge, file hash suffix, linked evidence status, delivery identity, evidence date, license category, and all release blockers. `currentBestCandidate` is relabeled as the research favorite. A separate production-readiness presentation is derived from the current candidate and its exact license; no “accepted” review disposition or research-favorite checkbox implies legal clearance.

The license section adds the new evidence fields plus two JSON-only actions: import a license package/compatible external manifest, and export the normalized license package. Import shows a preflight summary and commits only a conflict-free plan. ZIP selection is rejected with a message explaining that audio and manifests must be chosen separately.

## Atomicity, privacy, and security

- Project, license-package, and external-manifest inputs are fully parsed, normalized, validated, and conflict-checked before state replacement.
- A failed import leaves the project object, local storage, selected candidate, object URLs, playback element source/current time/state, and invalid-state quarantine unchanged.
- External analysis may create object URLs for the active session, but never persists those URLs or file bytes.
- The importer performs no network requests and does not dereference evidence URLs.
- Direct download URLs, signed query strings, and browser-authenticated URLs are not portable license evidence.
- SHA-256 proves byte identity and detects accidental corruption; it is not ownership proof, authentication, or legal clearance.
- Existing 16 MiB project state and 48 MiB Markdown-document limits remain unchanged. The license package uses its own smaller limits.

## Compatibility and versioning

- Project schema becomes version 3.
- StyleSpec remains version 1.
- Markdown handoff envelope remains version 1.
- License package starts at version 1.
- New projects use tool version `loop-bgm-lab/1.3.0`; imported older tool-version strings are preserved.
- JSON and Markdown round trips preserve every v3 source and license fact.
- Existing v1/v2 projects import through conservative migration; future project, envelope, and package versions are rejected.

## Verification

Core tests must prove schema migration, every source variant, exact candidate-license hash linking, Suno run/output binding, external experiment isolation, license classification and blockers, package idempotence/conflict atomicity, v4 mapping and field stripping, size/version/key/path/secret rejection, and JSON/Markdown v3 round trips.

Browser tests must prove that an external candidate can be analyzed with no run, never changes a batch to downloaded, auto-links an exact imported license, remains blocked when evidence is missing or preview-only, shows ShareAlike separately, distinguishes research favorite from release readiness, preserves atomic import failure, and makes zero unexpected network requests. Migrated v2 candidates must display source-unconfirmed and remain unguessed.

Release verification must include focused Node tests, all Loop BGM tests, four responsive Chromium viewports, keyboard and reduced-motion checks, the full repository suite, Hub publication audit, exact public-file byte comparison, privacy scans, remote exact-head workflows, and a fresh online page check before the feature is called released.

## Acceptance criteria

- External and local-original audio can be analyzed without a Suno run or Suno batch mutation.
- No external file can be represented as Suno-generated without an exact run/output binding.
- License evidence links only by exact SHA-256; an external/local import with missing or ambiguous evidence is rejected, while preview, NC, SA, ND, unknown, and incomplete rights evidence remain explicit release blockers.
- The external v4 manifest can be converted into a safe license package without carrying audio identity paths or direct download transport fields.
- A license-package conflict causes zero project mutation.
- Schema v1/v2 projects migrate without provenance invention, while v3 JSON and Markdown restore losslessly.
- The public tool communicates research usefulness and production readiness as different states.
