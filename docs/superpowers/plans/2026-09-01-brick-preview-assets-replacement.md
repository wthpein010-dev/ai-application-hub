# 砖块小人角色预览资源替换实施计划

> 执行方式：当前会话内按 TDD 连续完成，不在计划阶段暂停。

## 目标

将用户指定的本地美术预览目录中可用的完整角色图同步到 AI Application Hub 的砖块小人图鉴。新目录当前包含角色 ID `10–44` 共 35 张 PNG；网页优先显示这些整图，目录中缺失的 ID `1–9` 和 `45` 继续使用现有 Unity 分层合成，保证 45 个角色全部可查看。正式角色名、获取文案和 `GalleryDesc` 仍来自本地正式 Unity 工程，不得被美术文件名覆盖。

## 资源与数据契约

- 仓库只保存稳定文件名 `assets/preview/<角色ID>.png`，不得写入本机 `J:` 路径。
- `characters.json` 仅为已有预览的角色增加相对路径字段；缺失预览的角色不增加空路径。
- 同步器从环境变量读取源目录，校验 PNG、ID、重复 ID 和角色清单范围，复制后清理不再存在的受管预览 PNG，但保留非 PNG 文件。
- Unity 同步器重新生成角色文案和分层资源时，必须自动保留仓库中已发布预览图的引用。
- 渲染器优先使用完整预览图；无预览时回退到原有 body/block/dress/head 分层和四肢合成。

## TDD 与实现步骤

1. 在 `tests/brick-gallery-data.test.mjs` 增加同步器行为测试：稳定 ID 文件名、35/10 混合模式、未知 ID/重复 ID拒绝、过期受管 PNG 清理、本地路径不落数据。先运行并确认因功能缺失而失败。
2. 增加预览资源同步脚本，并让 Unity 同步器在重写数据时重新发现已发布预览图；运行聚焦数据测试至通过。
3. 在 `tests/brick-gallery-page.test.mjs` 与 `tests/brick-gallery-browser-smoke.mjs` 增加真实渲染契约：整图优先、分层回退、居中 `object-fit: contain`、45 个详情均加载成功。先确认旧渲染失败，再最小修改 `app.js` 与 `styles.css`。
4. 使用新同步器从只读美术目录复制 35 张 PNG，并核对源/仓库逐文件 SHA-256、透明通道、尺寸和 ID 映射；确认 Unity 源目录和美术源目录无修改。
5. 更新 Hub 展示图、视频封面、教程视频和单行中文字幕，使可见角色资源与公开体验一致。
6. 运行砖块图鉴专项静态测试、真实浏览器测试、随身小物市场回归、发布审计和完整 `node --test`；覆盖 `1440×900`、`750×1334`、`390×844`，逐一打开 45 个角色，检查图像居中、换行诊断、深链、历史、焦点和横向溢出。
7. 普通提交并推送功能分支，创建 PR、合并到 `main`；等待精确合并 SHA 的 GitHub Pages 与完整工作流成功，再做公网 HTTP、哈希、MP4 Range 和真实浏览器验收。
8. 更新 `AI-Application-Hub.md` 与 `麻将竞品.md` 的已确认项目状态，记录源数量、回退数量、合并 SHA、测试和公开链接。

## 验收标准

- 角色 ID `10–44` 使用新完整预览图，ID `1–9`、`45` 正常显示原分层图；总数仍为 45，默认全解锁、3×4、4 页。
- 角色图片在卡片和详情中视觉居中，不拉伸、不裁切、不出现本地路径或缺图请求。
- 正式文案、真实换行诊断、搜索、分页、收藏、分享、详情前后切换、深链、Back/Forward 和焦点管理无回退。
- 展示图与视频反映新资源；字幕任一时刻仅一行。
- 所有相关本地测试、完整 CI、Pages 和公网逐项验收通过后才报告完成。
